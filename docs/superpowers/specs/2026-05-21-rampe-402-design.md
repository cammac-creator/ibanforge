# IBANforge — Rampe d'accès dans la réponse 402 — Design Spec

> Date : 2026-05-21 · Statut : validé · Origine : rapport `docs/business/analyse-trafic-2026-05-21.md` (priorité P1)

## Objectif

Quand un appel non authentifié atteint un endpoint payant, la réponse `HTTP 402` doit présenter **les trois voies d'accès** — clé gratuite, packs de crédits (carte ou USDC), pay-per-call x402 — au lieu d'en taire une. But : convertir une partie des 13 100+ requêtes qui tapent le 402 sans suite (~0 conversion aujourd'hui).

## 1. Contexte

Sur `/v1/*`, un appel sans clé API ni paiement reçoit un `402`. Le middleware `@x402/hono` répond un corps `{}` ; `enrich402Middleware` (`src/middleware/enrich-402.ts`, « Path 1 ») reconstruit alors un corps complet depuis la config `PRICING`.

Corps 402 produit aujourd'hui en production (vérifié le 2026-05-21 sur `POST /v1/iban/validate`) — 8 clés :

`x402Version` · `error` · `message` · `accepts` · `free_tier` · `x402` · `documentation` · `llms`

La clé gratuite (`free_tier`) et le rail x402 sont **déjà exposés**. Ce qui manque :

- **Aucun bloc « packs de crédits ».** Ni le paiement par **carte** (Stripe), ni les **bundles prépayés USDC** (`POST /v1/credits/buy/:bundle`) n'apparaissent dans le 402.
- Le `message` ne cite que 2 voies sur 3 (« free API key OR pay per call via x402 »).

Conséquence : un développeur sans wallet crypto, ou un agent qui préférerait un règlement unique pour 5 000 appels, n'a aucune indication que ces options existent.

## 2. Décision

Exposer le rail « packs de crédits » dès maintenant :

- Le lien **carte** pointe vers `https://api.ibanforge.com/#pricing` — la page qui affiche déjà les 3 chemins et les 3 boutons packs.
- Les **Stripe Payment Links** ne sont pas encore configurés (placeholders `STRIPE_PAYMENT_LINK_*` dans `landing.ts`). Compromis assumé (§7) : on livre la rampe maintenant ; les liens seront collés ultérieurement sans retoucher le 402.
- Le rail **bundles USDC** (`/v1/credits/buy/:bundle`) est pleinement fonctionnel et exposé directement.

## 3. La réponse 402 enrichie

### Nouveau bloc `credit_packs`

Inséré entre `free_tier` et `x402` (ordre : gratuit → prépayé → pay-per-call) :

```jsonc
"credit_packs": {
  "description": "Prepaid credits — never expire, lower per-call cost than retail",
  "pay_by_card": "https://api.ibanforge.com/#pricing",
  "pay_by_usdc": "POST /v1/credits/buy/1k|5k|25k  ·  list: GET /v1/credits/bundles",
  "pricing": "1k = $5 · 5k = $20 (-20%) · 25k = $80 (-36%)"
}
```

### `message` élargi

De :
> `Authentication required. Get a free API key (200 req/month) or pay per call via x402.`

À :
> `Authentication or payment required. Three ways in: a free API key (200 req/month), prepaid credit packs (card or USDC), or pay-per-call via x402.`

(Conserve la sous-chaîne « API key », attendue par un test existant.)

Les blocs `free_tier`, `x402`, `accepts`, `documentation`, `llms` sont **inchangés**.

## 4. Changements de code — `src/middleware/enrich-402.ts`

### 4.1 Fonction partagée `buildAccessRamp()`

Source unique de vérité pour les blocs lisibles. Retourne :

```
{ message, free_tier, credit_packs, x402, documentation, llms }
```

- `free_tier` : champs **inchangés** (`description`, `signup`, `usage`).
- `x402` : champs **inchangés** (`description`, `protocol_docs`, `discovery`, `bazaar`).
- `credit_packs` : nouveau (§3).
- `message` : élargi (§3).

### 4.2 Path 1 — corps `{}` / vide (chemin de production)

Le `body` reconstruit devient :

```
{ x402Version: 1, error: 'payment_required', accepts, ...buildAccessRamp() }
```

Path 1 gagne `credit_packs` et le `message` élargi ; tout le reste est identique au comportement actuel.

### 4.3 Path 2 — corps avec `accepts` (filet de sécurité)

Path 2 ne se déclenche pas avec la version actuelle de `@x402/hono` (corps `{}`), mais reste un filet si ce comportement change. Après l'injection `outputSchema` :

```
const enriched = { ...parsed, ...buildAccessRamp() };
enriched.accepts = patchedAccepts;        // accepts patchés réassignés
```

- `...parsed` d'abord → préserve tout champ inconnu produit par `@x402/hono` (dont `x402Version`, `error`).
- `...buildAccessRamp()` ensuite → ajoute la rampe ; le `message` de la rampe prime (voulu).
- `accepts` n'est **jamais** dans `buildAccessRamp()` ; il est réassigné explicitement aux entrées patchées → l'injection `outputSchema` (recette Bazaar) reste intacte.
- `x402Version` et `error` sont garantis présents (fallback si absents de `parsed`).

## 7. Compromis assumés

- **Lien carte → `api.ibanforge.com/#pricing`.** C'est la seule page affichant les 3 chemins et les boutons packs. Les Stripe Payment Links y sont des placeholders ; tant qu'ils ne sont pas collés, les boutons affichent « not yet configured — email support@ ». Le 402 reste honnête (la page existe, le rail s'activera sans le retoucher), mais le parcours carte n'est pleinement fonctionnel qu'après configuration des Payment Links.
- **`message` réécrit.** On change le texte d'un champ déjà servi ; un seul test en dépend (sous-chaîne « API key »), préservée.
