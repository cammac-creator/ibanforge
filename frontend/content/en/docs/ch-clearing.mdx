# Swiss clearing: look up an IID or QR-IID

`GET /v1/ch/clearing/:iid` looks up a SIX BankMaster reference for a Swiss or Liechtenstein institution. It returns available bank details, its BIC and payment-system participation indicators. It does not verify an account or its holder, or guarantee payment acceptance.

Documentation reviewed on **4 November 2026**. A bank’s values can change: read the current response instead of fixing a captured example in an integration.

## First call with a reusable key

Create or retrieve an [API key](/docs/api-keys), then set `IBANFORGE_API_KEY` in the program’s environment. Keep the same key for subsequent requests; do not embed it in public page code.

```bash
curl --fail-with-body -sS https://api.ibanforge.com/v1/ch/clearing/230 \
  -H "X-API-Key: ${IBANFORGE_API_KEY}"
```

`X-API-Key` accepts an `ifk_…` key; `Authorization: Bearer ifk_…` also works. The allowance and cost depend on the access option described on the [pricing page](/pricing). x402 is another access option, not a requirement. The keyless REST trial for single IBAN validation does not extend to this clearing route.

## Which identifier should you send?

| Input | Treatment |
|---|---|
| One to five digits | Left-padded to five digits: `230` becomes `00230`. |
| QR-IID from `30000` to `31999` | The lookup accepts the QR number directly; do not calculate an ordinary IID from it. |
| Old IID redirected in the served table | The response may name its successor and add `redirected_from`. Keep the requested identifier for review. |

An accepted syntax does not prove that the identifier occurs in the data. The QR range describes an identifier type, not an institution at every number.

## Read fields within their scope

| Field | Meaning |
|---|---|
| `found` | A reference was found in the consulted data. |
| `iid` | IID of the resolved institution. For a QR row associated with an ordinary IID, that ordinary IID is returned. If the row has no such association, the API keeps its IID instead of inventing one. |
| `institution`, `address`, `bic` | Available institution, bank address and BIC. The address is not the payee’s address. |
| `payment_services` | The consulted row’s `sic`, `rtgs_chf`, `instant_payments_chf`, `eurosic`, `lsv_bdd_chf` and `lsv_bdd_eur` indicators. These are not live availability checks for an account. |
| `sic_iid` | Participant number of the consulted SIX row. A QR lookup can differ from the participant number on the ordinary IID row. |
| `qr_iid` | Available QR identifier, including on some ordinary-IID lookups; `null` when none is resolved. |
| `qr_iid_source` | `register`: association from register rows; `headquarters`: inherited from the head office; `null`: no resolved association. |
| `qr_iids` | Added when multiple QR-IIDs are resolved. The singular field keeps the lowest; reading only it loses the other values. |
| `is_qr_iid` | `true` when the looked-up row is a QR-IID. The presence of `qr_iid` alone does not mean the request was for a QR number. |
| `valid_on` | Validity date of the SIX row. It is neither the last download date nor a freshness promise. |
| `redirected_from`, `note` | Optional redirection and explanation. Do not automatically replace supplier bank details. |

A cantonal-bank response may also contain `state_guarantee`, with its own source. This separate information does not validate an account or payment.

## Missing results and errors

After an authorised call, **HTTP 200 with `found: false`** and `error: "clearing_not_found"` is a lookup result. The served data did not provide the reference; this does not mean an account is closed or the institution necessarily ceased to exist.

Read the HTTP status before the business result. The route has a `400` response for an invalid IID format; access checks can respond before the lookup. A `402` for uncovered access is not a missing IID. See [limits and errors](/docs/errors) for other cases.

## Start from an IBAN or a QR-bill

[IBAN validation](/docs/iban-validate) can include a `clearing` block for CH/LI when a reference is resolved. Use that route when you already have the full IBAN.

A QR-bill can use an **ordinary IBAN** or a **QR-IBAN**, depending on the reference. The [QR-IBAN guide](/docs/swiss-qr-iban) separates number recognition, bank lookup and Swiss QR Code text checks. Never construct a customer’s QR-IBAN from a returned IID.
