# Finnish bank code check: monetary institution codes

Finnish bank codes come from the **Finance Finland** list of monetary institution codes, and they behave unlike the national registers we read in Germany, Austria or Belgium in three ways.

First, the code is not a fixed slice of the IBAN: Finnish institution codes run **one to four characters** at the head of the BBAN, so the check reads the *longest allocated prefix* rather than a positional cut. Take a fixed three-digit slice of `FI21 1234 5600 0007 85` and you would ask about `123` and deny the country's largest banking group, whose code is simply `1`.

Second, **Finnish codes are allocated to banking groups, not to individual institutions.**

Third, and this is the one to design around, **the list we hold is partial.** It is a transcription of the Finance Finland publication dated 15 October 2025, and nothing refreshes it automatically. Since 16 September 2026 the API therefore treats it as a list that names holders without refusing anyone: a hit is served, a miss is not a denial.

## One call

```bash
curl -X POST https://api.ibanforge.com/v1/iban/validate \
  -H "Content-Type: application/json" \
  -d '{"iban": "FI2112345600000785"}'
```

The response is abridged below to the block this page is about; the same answer also carries the `bic` object, whose `code` here is `NDEAFIHHXXX`.

```json
{
  "valid": true,
  "bank_code_check": {
    "value": "1",
    "status": "verified",
    "match": "register",
    "register": "Finance Finland monetary institution codes (allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial)",
    "authoritative": false,
    "as_of": "2025-10",
    "institution": { "name": "Nordea Bank", "street": null, "post_code": null, "town": null, "country": "FI" }
  }
}
```

This is Finland's **official example IBAN**, and it is the counter-example to the broken ones: unlike the Belgian, Swiss and Austrian official examples, whose bank codes are [allocated to nobody](/blog/2026-08-06-example-ibans-unallocated-bank-codes), the Finnish example resolves cleanly, because code `1` is real and belongs to the Nordea banking group.

## Read the register string, it is doing work

Look at what `register` says: *"allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial"*. Both clauses ship **inside the response**, because a Finnish answer claims less than a German or Austrian one, in both directions:

| Register | A `verified` result means | A code the list does not hold means |
|---|---|---|
| DE, AT, BE, SK, BG, CH / LI | the code is allocated to **this named institution** | not allocated: `not_in_register`, `authoritative: true` |
| **FI** | the code is allocated to **this banking group** | nothing: the answer falls back to our composite map, `authoritative: false` |

## What a miss means here

A Finnish code the list does not carry is **never refused**. The answer falls through to what any country without a register gets: our composite bank-code map, `authoritative: false`, and at worst `status: "not_in_register"` with `reason: "absent_from_reference_data"`, which says something about our data and nothing about the code. You will never see `not_allocated` for Finland. The IBAN's checksum keeps saying `valid: true` beside it either way.

The reason is the list itself: a transcription that nothing refreshes cannot tell a new or renamed institution from a code nobody holds, and a refusal read off an eleven-month-old list is not something a payment engine should stop on. Finland goes back to the registers that settle a negative once the list is re-read against a current publication.

## The institution block for Finland

A hit carries an `institution` block with the name of the **banking group** the code belongs to (`Nordea Bank` for code `1`), and no address: the list publishes none, and a group-level code has no single seat to describe. `authoritative: false` stays beside it, for the reason above.

## Freshness

`as_of` is the date of the list itself, `2025-10`, not our monthly refresh: nothing re-reads the Finance Finland publication automatically, and an answer you act on has to say how old its list is.

## The honest limits

- **A hit confirms the group, not the branch or the institution.** If your process needs to know exactly which member bank holds the account, a Finnish bank-code check is not the tool.
- **A miss proves nothing.** The list is partial and dated; an absent code is not a refusal.
- **We check the bank code, never the account or its holder.** Nothing in this answer looks past the code at the head of the BBAN.
- **Prefix length matters.** The check uses the longest allocated prefix; a naive fixed-width slice of a Finnish BBAN will produce wrong lookups against any register, including this one.
- **No addresses.** The list names groups and publishes no seat.
