# Batch IBAN validation

Check 1 to 100 IBANs per request. Each entry has its own result: an invalid IBAN removes neither the other results nor its own row. This check does not establish account existence or account-holder identity.

```text
POST https://api.ibanforge.com/v1/iban/batch
```

## Access and cost

An **API key** or an x402 payment is required. The keyless single-validation trial does not cover this route. Keep the same key to track its usage and top it up; do not place it in a public page or repository.

With a key, every submitted entry consumes one allowance unit or prepaid credit, including duplicates and invalid IBANs. `cost_usdc` is then `0`; that does not mean the batch consumes no units. A batch larger than the available units is rejected in full with `402`, with no partial results. Allowance and credits can jointly fund a batch.

With x402, the price is **0.002 USDC per IBAN**. An x402 client signs the requirements returned with `402`; an empty header is not a payment. The [x402 guide](/docs/x402) covers v2 `PAYMENT-SIGNATURE` and v1 `X-PAYMENT` compatibility.

## Request with a key

These examples use a key already stored in the server-side `IBANFORGE_API_KEY` environment variable. [Get and retain a key](/docs/api-keys). The IBANs below are documentation examples, not accounts to pay.

```bash
curl --fail-with-body --silent --show-error \
  https://api.ibanforge.com/v1/iban/batch \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${IBANFORGE_API_KEY:?}" \
  -d '{"ibans":["CH1000230000000012345","DE89370400440532013000","INVALID123"]}'
```

`ibans` is an array of 1 to 100 strings. The aliases `iban_list` and `list` are also accepted; use one field. The validator normalizes spaces, ASCII hyphens and lowercase letters. An empty string remains an invalid entry, while a number or object makes the entire request invalid.

### Python

```python
import json
import os
import urllib.request

ibans = ["CH1000230000000012345", "DE89370400440532013000", "INVALID123"]
request = urllib.request.Request(
    "https://api.ibanforge.com/v1/iban/batch",
    data=json.dumps({"ibans": ibans}).encode(),
    headers={
        "Content-Type": "application/json",
        "Authorization": "Bearer " + os.environ["IBANFORGE_API_KEY"],
    },
    method="POST",
)
with urllib.request.urlopen(request, timeout=30) as response:
    data = json.load(response)

if len(data["results"]) != len(ibans):
    raise ValueError("results / ibans")
for index, result in enumerate(data["results"]):
    print(json.dumps({"index": index, "input": ibans[index], "result": result}))
```

### Node.js / TypeScript

```typescript
const key = process.env.IBANFORGE_API_KEY;
if (!key) throw new Error("IBANFORGE_API_KEY");
const ibans = ["CH1000230000000012345", "DE89370400440532013000", "INVALID123"];
const response = await fetch("https://api.ibanforge.com/v1/iban/batch", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${key}` },
  body: JSON.stringify({ ibans }),
  signal: AbortSignal.timeout(30000),
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const data = await response.json();
if (!Array.isArray(data.results) || data.results.length !== ibans.length) {
  throw new Error("results / ibans");
}
for (const [index, result] of data.results.entries()) {
  console.log(JSON.stringify({ index, input: ibans[index], result }));
}
```

## Read the response

A `200` means the batch was processed, not that every IBAN is valid. `results[i]` corresponds to `ibans[i]`, in the same order without deduplication. Keep your source-row identifier alongside that index.

| Field | Meaning |
|---|---|
| `results` | One validation response per entry; inspect `valid`, then the checks and their sources. |
| `count` | Number of processed entries, including duplicates. |
| `valid_count` | Number with `valid: true`; not a count of existing accounts or authorized payments. |
| `cost_usdc` | USDC amount for this call; zero with a key. |
| `processing_ms` | Processing duration for this response, not a latency commitment. |
| `attribution` | Source credits when carried by the response; retain them with the results. |

Each entry follows the [single-validation reference](/docs/iban-validate). `bank_code_holder`, `bank_code_check`, `bic`, `checks` and their sources distinguish confirmed references, inferences and unavailable data. Some blocks are absent or `null` depending on the IBAN and available sources. Batch validation does not return the additional [compliance](/docs/compliance) block.

## Errors and resuming work

| Status / code | Handling |
|---|---|
| 400 `invalid_json` | Malformed JSON. |
| 400 `invalid_request` | Missing field, expected array or non-string entry. |
| 400 `empty_batch` | Empty array. |
| 400 `batch_too_large` | More than 100 entries; split the input before calling. |
| 402 | Missing or unusable key, or insufficient units; read the response body and headers. |
| 429 | Rate limit; wait for `Retry-After`. |

A `200` can contain `valid: false` with `error` and `error_detail`. After a network failure during a submitted request, processing may have occurred: do not automatically replay the entire batch as if it consumed nothing. Retain completed rows and check key usage. An unknown x402 settlement outcome also needs investigation before another payment.
