*Updated 4 November 2026.*

An IBAN validation API helps software teams check account-number structure and look up bank reference data. Its useful place is often **before a record enters the accounting system**: when a supplier submits bank details, an invoice is extracted, or a migration file is prepared.

IBANforge does **not** verify that an account exists, is open or belongs to a named person or company. It does not execute payments. The five workflows below are integration patterns, not customer case studies or measured savings.

## 1. ERP migrations: review the supplier master before import

**For:** ERP integrators and teams moving accounting systems.

A migration file can contain missing BICs, mistyped IBANs and bank codes marked as retired. A checksum alone cannot explain all three. Send a sample to the [batch endpoint](/docs/iban-batch), retain the original records and prepare a separate review file.

Read `valid` for structure, `bank_code_check` for the bank-code evidence and `bic.authoritative` for the strength of the IBAN-to-BIC pairing. An unavailable register is an unanswered question. It is not an invalid account and it is not permission to overwrite an existing BIC.

**Start here:** the [ERP migration recipe](/blog/2026-09-02-missing-bank-details-before-an-erp-migration) includes a downloadable Python example. For a one-off file without integration work, use the [file audit](/audit).

## 2. Invoice processing: check what OCR extracted

**For:** document-processing vendors and accounts-payable software.

Extract an IBAN from an invoice, then check the candidate before proposing it for the supplier record. IBANforge validates the supplied value; it does not read the invoice or decide whether that invoice is genuine.

A passing checksum does not rule out invoice fraud: an attacker can supply a valid IBAN. Keep approval of a changed bank account separate, using a contact channel already known to your organisation. Do not replace the supplier's bank details merely because the new number passes validation.

Use [batch validation](/docs/iban-batch) for several candidates. Preserve the link between each result and its source document, and treat an HTTP error as an unfinished check rather than a successful one.

## 3. Supplier onboarding: separate bank evidence from identity

**For:** procurement platforms, supplier portals and accounting products.

When a supplier enters bank details, return a specific result: invalid format, bank identified by a register, indicative match, or lookup unavailable. Show the source and its date where reference data informs a decision.

`checks.account_exists` and `checks.payee_name` remain `not_checked`. The name in `bic.bank_name` names a bank, not the account holder. Neither a bank name nor an issuer classification establishes the supplier's identity.

If your workflow needs a name-to-account check, that is a separate service such as the payment provider's Verification of Payee. See [what IBAN validation and VoP each answer](/docs/vop).

## 4. Payment forms: give useful feedback without promising settlement

**For:** payroll tools, billing products and payment-service integrators.

Check the IBAN on your server when a form is submitted. Keep an API key on the server; never embed it in browser JavaScript. For a structure-only check without reference data, the [open-source library](https://github.com/cammac-creator/iban-core) can be sufficient.

This Node.js example makes one authenticated validation call. Supply `IBANFORGE_API_KEY` through your server's environment:

```javascript
const key = process.env.IBANFORGE_API_KEY;
if (!key) throw new Error("IBANFORGE_API_KEY manque");

const response = await fetch("https://api.ibanforge.com/v1/iban/validate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${key}`,
  },
  body: JSON.stringify({ iban: "DE89370400440532013000" }),
  signal: AbortSignal.timeout(15000),
});
if (!response.ok) throw new Error(`Validation indisponible : HTTP ${response.status}`);
const result = await response.json();
console.log(result.valid, result.bank_code_holder, result.checks);
```

`valid: true` describes the IBAN's structure and checksum. Read the separate national check-digit and bank-code results as well. Country membership in SEPA does not establish the reachability of a particular bank or account; the [validation reference](/docs/iban-validate) explains the bank-level fields. None of these checks guarantees a payment will settle.

## 5. AI tools: return evidence to the workflow

**For:** developers adding financial-data tools to assistants.

The [MCP interface](/docs/mcp) exposes IBAN validation and BIC lookup to compatible clients. Use the structured result to explain which checks passed, which are inferred and which were not performed. Preserve source credits and limitations when presenting the answer.

An assistant should not treat `valid: true` as approval to change a supplier's bank account or send money. Payment authorisation and account-change approval belong to the surrounding application and its controls.
