A supplier form, an OCR-extracted invoice and a data migration can all contain an IBAN. Start by distinguishing a structural error, an available bank reference and information that remains unknown. They need different handling.

IBANforge checks IBAN structure and looks up available bank references. It confirms **neither account existence nor the account holder, and does not authorise payment**. The examples below are development inputs, not payment instructions.

## 1. Make a first call without a key

The keyless trial is available on `POST /v1/iban/validate`. Its allowance and renewal are described in the [validation reference](/docs/iban-validate). The response’s `trial` block gives the applicable balance and reset time; this trial does not provide keyless access to every route.

```bash
curl --fail-with-body --max-time 15 \
  https://api.ibanforge.com/v1/iban/validate \
  -H 'Content-Type: application/json' \
  -d '{"iban":"CH1000230000000012345"}'
```

HTTP 200 means the request was processed. You still need to inspect `valid` and the other checks: an invalid IBAN can also return HTTP 200. If the trial is exhausted, do not loop over the same call. Read the error and follow the [onboarding guide for a retained key](/docs/onboarding). This example creates no payment signature.

## 2. Read the result within its scope

| Field | What to read |
|---|---|
| `valid` | Structural validation result; it does not summarise every additional bank or national check. |
| `checks` | Individual checks, including failures and unknown results. Inspect the national check when available. |
| `bank_code_holder` | Identification of the bank-code holder, not the account holder’s identity. |
| `bank_code_check` | Reference consulted, result, scope and `as_of` date. An unavailable or incomplete source does not establish non-existence. |
| `bic` | A BIC, when found. Read `basis`, `authoritative`, `source` and `as_of`; the block may be absent or null. |
| `sepa` and VoP | Country, bank or register information depending on the field; no payee-name verification result. |

A missing BIC does not by itself make an IBAN invalid. A confirmed bank reference does not validate the account. [Coverage by source](/docs/data-sources) and the [VoP register guide](/docs/vop) explain these limits. Preserve the findings and their provenance before deciding how to present them to your user.

## 3. Reuse the same key on your server

For repeated calls, create a key once using the [API key documentation](/docs/api-keys), then store it in `IBANFORGE_API_KEY`. Do not create a new key on every run. Allowances and paid options are described on the [pricing page](/pricing); these examples buy no credits or subscription.

### Python, using the standard library

This code runs on your server. It bounds the wait, checks the HTTP status before decoding the response, and does not follow redirects. Its printed summary omits the input IBAN; retain the full response only in storage appropriate for your application.

```python
import http.client
import json
import os

key = os.environ.get("IBANFORGE_API_KEY", "").strip()
if not key:
    raise SystemExit("IBANFORGE_API_KEY is required")

connection = http.client.HTTPSConnection("api.ibanforge.com", timeout=10)
try:
    connection.request(
        "POST", "/v1/iban/validate",
        body=json.dumps({"iban": "CH1000230000000012345"}),
        headers={"Content-Type": "application/json", "Authorization": f"Bearer {key}"},
    )
    response = connection.getresponse()
    if response.status != 200:
        raise SystemExit(f"API HTTP {response.status}")
    result = json.load(response)
finally:
    connection.close()

if not isinstance(result, dict) or type(result.get("valid")) is not bool:
    raise SystemExit("Unexpected API response")
print(json.dumps({
    "valid": result["valid"],
    "bank_code_holder": result.get("bank_code_holder"),
    "bic": (result.get("bic") or {}).get("code"),
}))
```

### Server-side TypeScript or JavaScript

Example for Node.js 22 or later. Do not put a secret key in JavaScript delivered to a browser. For a web form, call from your server; see the [API reference](/docs/iban-validate) for errors and authentication.

Save the block as `first-call.mjs`, then run `node first-call.mjs`: top-level `await` requires an ES module.

```typescript
const key = process.env.IBANFORGE_API_KEY?.trim();
if (!key) throw new Error('IBANFORGE_API_KEY is required');

const response = await fetch('https://api.ibanforge.com/v1/iban/validate', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${key}` },
  body: JSON.stringify({ iban: 'CH1000230000000012345' }),
  signal: AbortSignal.timeout(10_000),
  redirect: 'error',
});
if (response.status !== 200) throw new Error(`API HTTP ${response.status}`);
const result = await response.json();
if (typeof result?.valid !== 'boolean') throw new Error('Unexpected API response');
console.log({
  valid: result.valid,
  bank_code_holder: result.bank_code_holder ?? null,
  bic: result.bic?.code ?? null,
});
```

These examples stop on HTTP errors and perform no automatic retries. A network error or timeout must remain distinct from an “invalid IBAN” result.

## 4. Look up a BIC already supplied

If the document already contains a BIC, [BIC lookup](/docs/bic-lookup) retrieves its bank reference. With the same key environment variable set:

```bash
curl --fail-with-body --max-time 15 \
  https://api.ibanforge.com/v1/bic/UBSWCHZH80A \
  -H "Authorization: Bearer ${IBANFORGE_API_KEY}"
```

This lookup does not prove that the BIC belongs to the supplied IBAN. If the existing details and the retrieved reference differ, preserve both and request a review rather than silently overwriting the supplier record.

## 5. Move to a small batch, then a review workflow

[Batch validation](/docs/iban-batch) needs its own access: the keyless single-validation trial does not apply to it. The first batch below contains two demonstration values, one with an incorrect checksum.

```bash
curl --fail-with-body --max-time 15 \
  https://api.ibanforge.com/v1/iban/batch \
  -H "Authorization: Bearer ${IBANFORGE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"ibans":["CH1000230000000012345","CH0000230000000012345"]}'
```

Check the result count and the correspondence of every IBAN before attaching results to file rows. A partial, reordered or unknown response must stop automatic attribution; preserve the original file. Do not infer the whole batch is valid from HTTP 200 alone.
