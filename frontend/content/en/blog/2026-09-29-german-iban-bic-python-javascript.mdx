Revised on 4 November 2026. These examples prepare a review of bank details; they do not authorise payments.

The [Bundesbank Bankleitzahlendatei](https://www.bundesbank.de/de/aufgaben/unbarer-zahlungsverkehr/serviceangebot/bankleitzahlen/download-bankleitzahlen-602592) associates German bank codes with their references and records planned deletions and successor codes. IBANforge exposes the consulted reference in `bank_code_check` and BIC provenance in `bic`. A correct checksum alone cannot provide this information.

Use these examples for supplier imports or data migration. They retain each input, its index and the full response, without replacing a BIC or choosing an account on the user's behalf.

## Reading the observation

| `observation` | Interpretation |
|---|---|
| `invalid_iban` | The API returned `valid: false`; read `error` and `error_detail` rather than assuming a typing mistake. |
| `outside_german_scope` | The IBAN is not German; these examples do not interpret another register's coverage. |
| `bank_code_retired` | Read the retirement and `superseded_by`; a successor code cannot reconstruct the account. |
| `bank_code_not_allocated` | The consulted register does not allocate the code, as dated in the response. |
| `bank_reference_found` | The bank-code result is `verified`, `authoritative: true`, with a source and date. This is not a verified account. |
| `review` | Any other result, including an unavailable, partial or undated source; preserve the uncertainty. |

Every row carries `review_required: true`. The names above belong to this review example, not the API contract. The complete result stays in `source_response`; the [validation reference](/docs/iban-validate) documents all its fields.

## Python 3.10 or later

Standard library only. Save the block as `review_iban.py`. Read the key from the `IBANFORGE_API_KEY` environment variable, not from source code. It is optional for the single-IBAN trial and required for the batch path below.

```python
import json
import os
from urllib.error import HTTPError
from urllib.request import Request, urlopen

API = "https://api.ibanforge.com"
KEY = os.environ.get("IBANFORGE_API_KEY", "").strip()


def normalise(value: str) -> str:
    if not isinstance(value, str):
        raise ValueError("IBAN must be a string")
    return "".join(value.split()).upper()


def post(path: str, payload: dict) -> dict:
    headers = {"Content-Type": "application/json"}
    if KEY:
        headers["Authorization"] = "Bearer " + KEY
    request = Request(API + path, data=json.dumps(payload).encode(),
                      headers=headers, method="POST")
    try:
        with urlopen(request, timeout=30) as response:
            return json.load(response)
    except HTTPError as error:
        if error.code == 429:
            raise RuntimeError("HTTP 429; Retry-After=" +
                               error.headers.get("Retry-After", "unknown")) from None
        if error.code == 402:
            raise RuntimeError("HTTP 402; inspect access and remaining allowance") from None
        raise RuntimeError(f"HTTP {error.code}") from None


def interpret(original: str, answer: dict, index: int) -> dict:
    if (not isinstance(answer, dict) or type(answer.get("valid")) is not bool
            or answer.get("iban") != normalise(original)):
        raise ValueError("Unexpected or misaligned API response")
    check = {} if answer.get("bank_code_check") is None else answer["bank_code_check"]
    bic = {} if answer.get("bic") is None else answer["bic"]
    if not isinstance(check, dict) or not isinstance(bic, dict):
        raise ValueError("Unexpected bank reference")
    for flag in ("authoritative", "retired"):
        if flag in check and type(check[flag]) is not bool:
            raise ValueError("Unexpected bank reference flag")
    observation = "review"
    if answer["valid"] is False:
        observation = "invalid_iban"
    elif not answer["iban"].startswith("DE"):
        observation = "outside_german_scope"
    elif check.get("retired") is True:
        observation = "bank_code_retired"
    elif (check.get("status") == "not_in_register"
          and check.get("reason") == "not_allocated"
          and check.get("authoritative") is True):
        observation = "bank_code_not_allocated"
    elif (check.get("status") == "verified" and check.get("authoritative") is True
          and check.get("register") and check.get("as_of")):
        observation = "bank_reference_found"
    return {"index": index, "input": original, "observation": observation,
            "review_required": True, "source_response": answer}


def review_one(iban: str) -> dict:
    normalise(iban)
    return interpret(iban, post("/v1/iban/validate", {"iban": iban}), 0)


def review_many(ibans: list[str]) -> list[dict]:
    if not isinstance(ibans, list):
        raise ValueError("Expected a list of IBAN strings")
    for iban in ibans:
        normalise(iban)
    if not ibans:
        return []
    if not KEY:
        raise ValueError("IBANFORGE_API_KEY is required for a batch")
    output = []
    for start in range(0, len(ibans), 100):
        batch = ibans[start:start + 100]
        body = post("/v1/iban/batch", {"ibans": batch})
        results = body.get("results") if isinstance(body, dict) else None
        if not isinstance(results, list) or len(results) != len(batch):
            raise ValueError("Unexpected batch length")
        output.extend(interpret(raw, result, start + offset)
                      for offset, (raw, result) in enumerate(zip(batch, results)))
    return output
```

## Server-side JavaScript, Node.js 20 or later

Save this block as `review-iban.mjs`. It uses the same environment variable and observations, with no additional package. Keep the key on the server.

```javascript
const API = "https://api.ibanforge.com";
const KEY = (process.env.IBANFORGE_API_KEY ?? "").trim();

function normalise(value) {
  if (typeof value !== "string") throw new Error("IBAN must be a string");
  return value.replace(/\s/g, "").toUpperCase();
}

function isObject(value) {
  return value !== null && typeof value === "object" && !Array.isArray(value);
}

async function post(path, payload) {
  const headers = { "Content-Type": "application/json" };
  if (KEY) headers.Authorization = `Bearer ${KEY}`;
  const response = await fetch(API + path, {
    method: "POST", headers, body: JSON.stringify(payload),
    signal: AbortSignal.timeout(30_000),
  });
  if (response.status === 429) {
    throw new Error(`HTTP 429; Retry-After=${response.headers.get("Retry-After") ?? "unknown"}`);
  }
  if (response.status === 402) throw new Error("HTTP 402; inspect access and remaining allowance");
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

export function interpret(original, answer, index) {
  if (!isObject(answer) || typeof answer.valid !== "boolean" || answer.iban !== normalise(original)) {
    throw new Error("Unexpected or misaligned API response");
  }
  const check = answer.bank_code_check ?? {};
  const bic = answer.bic ?? {};
  if (!isObject(check) || !isObject(bic)) throw new Error("Unexpected bank reference");
  for (const flag of ["authoritative", "retired"]) {
    if (flag in check && typeof check[flag] !== "boolean") throw new Error("Unexpected bank reference flag");
  }
  let observation = "review";
  if (answer.valid === false) observation = "invalid_iban";
  else if (!answer.iban.startsWith("DE")) observation = "outside_german_scope";
  else if (check.retired === true) observation = "bank_code_retired";
  else if (check.status === "not_in_register" && check.reason === "not_allocated" && check.authoritative === true) {
    observation = "bank_code_not_allocated";
  } else if (check.status === "verified" && check.authoritative === true && check.register && check.as_of) {
    observation = "bank_reference_found";
  }
  return { index, input: original, observation, review_required: true, source_response: answer };
}

export async function reviewOne(iban) {
  normalise(iban);
  return interpret(iban, await post("/v1/iban/validate", { iban }), 0);
}

export async function reviewMany(ibans) {
  if (!Array.isArray(ibans)) throw new Error("Expected a list of IBAN strings");
  ibans.forEach(normalise);
  if (!ibans.length) return [];
  if (!KEY) throw new Error("IBANFORGE_API_KEY is required for a batch");
  const output = [];
  for (let start = 0; start < ibans.length; start += 100) {
    const batch = ibans.slice(start, start + 100);
    const body = await post("/v1/iban/batch", { ibans: batch });
    if (!isObject(body) || !Array.isArray(body.results) || body.results.length !== batch.length) {
      throw new Error("Unexpected batch length");
    }
    output.push(...body.results.map((result, offset) => interpret(batch[offset], result, start + offset)));
  }
  return output;
}
```

## Run a first example

After saving the module, these commands use a documentation IBAN. They call the API; they are not simulations.

```bash
python3 -c 'from review_iban import review_one; import json; print(json.dumps(review_one("DE89370400440532013000")))'
node --input-type=module -e 'import { reviewOne } from "./review-iban.mjs"; console.log(JSON.stringify(await reviewOne("DE89370400440532013000")))'
```

For a list, call `review_many([...])` in Python or `await reviewMany([...])` in JavaScript, with a retained key. The functions split the input into batches of at most 100 entries, keep duplicates and order, then check the length and IBAN of each response before associating it with a row. An empty list makes no request. A non-string input stops the entire list before any request.

A shortened, reordered or malformed response stops processing. Identical duplicates cannot be distinguished by their IBAN, so the row index remains necessary.

## Errors, consumption and resuming

- HTTP `200` can contain `valid: false`. The code keeps it as a business result.
- HTTP `402` stops processing: inspect the key, remaining allowance and the API response's `cause.reason` before retrying. These examples buy nothing and do not retry.
- HTTP `429` exposes `Retry-After` in the error; there is no retry loop.
- Other HTTP errors, a timeout, invalid JSON or an inconsistent response also stop processing. Do not turn them into an invalid IBAN result.

If a later batch fails, earlier batches may already have consumed units. These functions return the list only at the end: a durable import needs a checkpoint per batch, rather than restarting the whole file blindly. A timeout does not prove that the server counted nothing.

The first single-IBAN call can use the [keyless trial](/docs/onboarding). The batch path above uses an [API key](/docs/api-keys): each entry consumes one unit, including duplicates and invalid IBANs. `cost_usdc: 0` on a key does not mean zero consumption. Allowances, credits and other access options: [batch documentation](/docs/iban-batch) and [pricing](/pricing).

## Retain provenance, then decide in your own process

Keep `bank_code_check`, `bic`, their dates and `next_steps` with the result. The register edition date is neither a payment date nor the date of an account verification. A BIC may be missing even when the bank code is identified; a register can be unavailable, including for Germany. `review` is therefore a real possibility.

These examples do not establish account existence, ownership or sanctions clearance. A retired code does not supply replacement bank details that can be used automatically; supplier-change controls belong to the business process.
