# Codes banque finlandais : les codes d'établissements monétaires

Les codes banque finlandais viennent de la liste des **codes d'établissements monétaires de Finance Finland**, et ils se comportent autrement que les registres nationaux que nous lisons en Allemagne, en Autriche ou en Belgique, pour trois raisons.

D'abord, le code n'est pas une tranche fixe de l'IBAN : les codes d'établissement finlandais font **un à quatre caractères** en tête du BBAN, si bien que le contrôle lit le *plus long préfixe attribué* plutôt qu'une découpe positionnelle. Une tranche fixe de trois chiffres interrogerait un code que personne n'a reçu, et refuserait un groupe dont le code est plus court.

Ensuite, **les codes finlandais sont attribués à des groupes bancaires, pas à des établissements individuels.**

Enfin, et c'est le point à intégrer dans votre conception, **la liste que nous détenons est partielle.** C'est une transcription de la publication de Finance Finland datée du 15 octobre 2025, que rien ne rafraîchit automatiquement. Depuis le 16 septembre 2026, l'API la traite donc comme une liste qui nomme des titulaires sans refuser personne : un résultat est servi, une absence n'est pas un refus.

L'éditeur n'a jamais confirmé les conditions de réutilisation de la liste : depuis le 25 septembre 2026, l'API la lit dans un fichier privé, et non plus dans son dépôt public. Une réponse servie sans ce fichier dit que la liste n'a pas été consultée (`status: "unavailable"`), jamais qu'un code est refusé.

## Un appel

```bash
curl -X POST https://api.ibanforge.com/v1/iban/validate \
  -H "Content-Type: application/json" \
  -d '{"iban": "FI2112345600000785"}'
```

La réponse est abrégée ci-dessous au bloc dont traite cette page. Les valeurs propres à la liste (le code, le groupe et le mois de la liste) sont omises ici ; l'API les sert.

```json
{
  "valid": true,
  "bank_code_check": {
    "value": "…",
    "status": "verified",
    "match": "register",
    "register": "Finance Finland monetary institution codes (allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial)",
    "authoritative": false,
    "as_of": "…",
    "institution": { "name": "…", "street": null, "post_code": null, "town": null, "country": "FI" }
  }
}
```

C'est **l'IBAN d'exemple officiel finlandais**. `value` est le code attribué dont parle la réponse, qui peut compter moins de trois chiffres, et `institution.name` est le groupe bancaire qui le détient.

## Lisez la chaîne `register`, elle travaille

Regardez ce que dit `register` : *« allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial »*. Les deux précisions voyagent **dans la réponse**, parce qu'une réponse finlandaise affirme moins qu'une réponse allemande ou autrichienne, dans les deux sens :

| Registre | Ce que veut dire un résultat `verified` | Ce que veut dire un code absent de la liste |
|---|---|---|
| DE, AT, BE, SK, CZ, BG, CH / LI | le code est attribué à **cet établissement nommé** | non attribué : `not_in_register`, `authoritative: true` |
| **FI** | le code est attribué à **ce groupe bancaire** | rien : la réponse retombe sur notre carte composite, `authoritative: false` |

## Ce que signifie une absence ici

Un code finlandais que la liste ne porte pas n'est **jamais refusé**. La réponse retombe sur ce que reçoit tout pays sans registre : notre carte composite des codes banque, `authoritative: false`, et au pire `status: "not_in_register"` avec `reason: "absent_from_reference_data"`, qui parle de nos données et non du code. Vous ne verrez jamais `not_allocated` pour la Finlande. À côté, la clé de contrôle de l'IBAN continue de dire `valid: true` dans tous les cas.

La raison tient à la liste elle-même : une transcription que rien ne rafraîchit ne sait pas distinguer un établissement nouveau ou renommé d'un code que personne ne détient, et un refus lu dans une liste vieille de onze mois n'est pas une raison d'arrêter un paiement. La Finlande rejoindra les registres qui tranchent une absence dès que la liste aura été relue contre une publication à jour.

## Le bloc `institution` pour la Finlande

Un résultat porte un bloc `institution` avec le nom du **groupe bancaire** auquel appartient le code, sans adresse : la liste n'en publie pas, et un code de groupe n'a pas de siège unique à décrire. `authoritative: false` reste à côté, pour la raison ci-dessus.

## Fraîcheur

`as_of` est le mois de la liste elle-même, et non celui de notre rafraîchissement mensuel : rien ne relit automatiquement la publication de Finance Finland, et une réponse sur laquelle vous agissez doit dire l'âge de sa liste.

## Les limites honnêtes

- **Un résultat confirme le groupe, pas l'agence ni l'établissement.** Si votre processus doit savoir exactement quelle banque membre tient le compte, le contrôle du code banque finlandais n'est pas l'outil.
- **Une absence ne prouve rien.** La liste est partielle et datée ; un code absent n'est pas un refus.
- **Nous contrôlons le code banque, jamais le compte ni son titulaire.** Rien dans cette réponse ne regarde au-delà du code en tête du BBAN.
- **La longueur du préfixe compte.** Le contrôle utilise le plus long préfixe attribué ; une découpe naïve à largeur fixe d'un BBAN finlandais produira de mauvaises recherches dans n'importe quel registre, celui-ci compris.
- **Aucune adresse.** La liste nomme des groupes et ne publie aucun siège.
