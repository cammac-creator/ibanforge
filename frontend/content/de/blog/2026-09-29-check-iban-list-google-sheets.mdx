Eine Lieferantendatei enthält IBANs, deren Format und Bankzuordnung Sie prüfen möchten. Das IBANforge-Script für Google Sheets füllt fünf Spalten neben den Originaldaten. Es unterstützt die Durchsicht von Bankverbindungen; es bestätigt weder den Kontoinhaber noch eine Zahlung.

Beginnen Sie mit den Beispielen unten in einer eigenen Testtabelle. Die manuelle Installation erfolgt über Apps Script: Für die Formeln ist keine eigene Entwicklung nötig, die installierte Kopie muss aber gepflegt werden. Das Script ist nicht im Google Workspace Marketplace veröffentlicht.

## Installieren und eine kleine Liste ausprobieren

1. [Laden Sie die drei Apps-Script-Dateien herunter](/integrations/ibanforge-sheets-0de6709768d7.zip). Öffnen Sie **Erweiterungen → Apps Script** in Ihrer Testtabelle.
2. Ersetzen Sie `Code.gs`, legen Sie eine HTML-Datei namens `Sidebar` an und fügen Sie `Sidebar.html` ein. Blenden Sie in den Projekteinstellungen `appsscript.json` ein und ersetzen Sie den Inhalt durch das mitgelieferte Manifest. Speichern Sie.
3. Führen Sie `ibfShowSidebar` im Editor aus. Prüfen Sie die angeforderten Berechtigungen und autorisieren Sie das Script, wenn diese zu Ihrem Einsatz passen. Geben Sie Ihren IBANforge-Schlüssel in der Seitenleiste der Tabelle ein und wählen Sie **Test and save**. Der Schlüssel gehört nicht in eine Zelle. Die [Anleitung zu API-Schlüsseln](/de/docs/api-keys) erklärt Bezug und Abfrage des tatsächlich geltenden Limits.
4. Kopieren Sie die folgenden sechs Zeilen nach **A2:A7**, einschliesslich der Leerzeile. Das sind Dokumentationsbeispiele, niemals Zahlungsanweisungen.

```text
DE65100700000123456789
DE65 1007 0000 0123 4567 89

DE65100700000123456798
CH3130000000000000001
TEST
```

5. Lassen Sie **B2:F7** leer und setzen Sie `=IBAN_CHECK(A2:A7)` in **B2**. Die Formel belegt fünf Spalten, B bis F, und erhält die sechs Zeilen samt Leerzeile. Die ersten beiden Eingaben sind nach Entfernen der Leerzeichen identisch.

Falls das Einfügen die Leerzeile überspringt, stellen Sie sie vor dem Test wieder her. Behalten Sie die Originalspalte und ergänzen Sie eigene Prüfnotizen ab G. Eine Formel für den ganzen Bereich vermeidet einen separaten Apps-Script-Aufruf je Zeile.

## Die fünf Spalten lesen

| Spalte | Inhalt | Aussage |
|---|---|---|
| B | `TRUE` oder `FALSE` | API-Ergebnis `valid`: Format und IBAN-Prüfungen, nicht Existenz des Kontos |
| C | Bank oder leer | Name zum BIC, falls vorhanden, sonst Institutionsname aus der Bankcode-Prüfung |
| D | BIC oder leer | Von der API ermittelter BIC; eine leere Zelle lässt die Bankzuordnung offen |
| E | Bankcode-Status oder Validierungsfehler | Zusammenfassung, deren Aussage von der Quellenabdeckung abhängt |
| F | SEPA-Verfahren, `yes`, `no` oder leer | Zusammenfassung von `sepa`, keine Garantie für die Ausführung einer Überweisung |

`verified` bedeutet, dass eine Referenz gefunden wurde. `verified, retired` kennzeichnet zusätzlich einen als zurückgezogen markierten Code: Angaben und Quelle prüfen, ohne selbst einen anderen Bankcode einzusetzen. `not_in_register (not_allocated)` meldet ein Fehlen im verwendeten vollständigen Register zu dessen Stand; daraus folgt kein Betrugsnachweis. Ein unbekanntes Ergebnis bleibt unbekannt. `checksum_failed` meldet eine gescheiterte Prüfung, nicht deren Ursache.

Die Sheets-Zusammenfassung enthält weder Quelldatum und `authoritative` noch Registerdetails oder einen möglichen Nachfolgecode. Ein Bankname bedeutet deshalb nicht immer «durch das nationale Register bestätigt». Für eine nachvollziehbare Prüfung bewahren Sie die vollständige Antwort gemäss [Validierungsanleitung](/de/docs/iban-validate) auf oder nutzen den [Ablauf für Lieferantendateien](/de/blog/2026-09-06-creditor-file-checks-before-14-november). Registerwerte können sich ändern; dieser Versuch schreibt kein Bankergebnis und kein Quelldatum fest.

Für eine einzelne Ergebnisspalte verwenden Sie `=IBAN_VALID(A2:A7)`, `=IBAN_BANK(A2:A7)` oder `=IBAN_BIC(A2:A7)`. Die Aliase `IBAN_VALIDE`, `IBAN_BANQUE`, `IBAN_CONTROLE`, `IBAN_GUELTIG`, `IBAN_BANKNAME` und `IBAN_PRUEFUNG` rufen dieselben Funktionen auf. `IBAN_CHECK` erwartet genau eine Eingabespalte.

## Aufrufe, Cache und Verbrauch

Der Batch-Endpunkt verlangt einen Schlüssel. Das Script entfernt Leerzeichen, wandelt Zeichenketten in Grossbuchstaben um, überspringt leere Zellen und fasst Duplikate innerhalb einer Ausführung zusammen. Nicht im Cache vorhandene Werte werden in Gruppen von höchstens 100 gesendet. Jede übermittelte IBAN verbraucht eine Einheit, auch eine ungültige; es ist nicht eine Einheit pro HTTP-Anfrage. [Preise](/de/pricing) und Nutzungsbericht des Schlüssels zeigen das geltende Angebot und Guthaben.

Das Script fordert einen Cache von sechs Stunden an. [Google kann Einträge früher entfernen](https://developers.google.com/apps-script/reference/cache/cache); eine Neuberechnung kann weitere Einheiten verbrauchen. Gleichzeitig laufende Formeln garantieren keinen einzelnen Aufruf. Scheitert ein späterer Batch, können frühere Batches bereits Einheiten verbraucht haben; diese Ausführung schreibt ihren Cache erst am Ende. Es gibt weder automatischen Kauf noch automatische Wiederholung.

## Übermittelte Daten und geteilte Tabellen

Die Funktionen senden ihre Eingabezeichenketten, den Schlüssel im Authentifizierungsheader und `source=sheets` an `api.ibanforge.com`. Die Seitenleiste fragt auch die Schlüsselnutzung ab. Übergeben Sie nur die IBAN-Spalte, keine Namen oder Kommentare. [Apps Script führt Anfragen über Googles Infrastruktur aus](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app), nicht nur in Ihrem Browser.

Der Schlüssel liegt in den Nutzereigenschaften des Apps-Script-Projekts. Für benutzerdefinierte Funktionen dokumentiert Google den Zugriff auf die Eigenschaften des Tabelleneigentümers; Bearbeiter können auch das verknüpfte Script ändern. Dieses Verfahren garantiert keinen getrennten Schlüssel und kein eigenes Kontingent pro Mitarbeiter. Testen Sie in Ihrer eigenen Kopie und prüfen Sie die Zugriffe, bevor Sie eine aktive Tabelle teilen. Dazu die [Google-Regeln für Funktionen und Freigaben](https://developers.google.com/apps-script/guides/sheets/functions).

## Wenn die Tabelle einen Fehler zeigt

| Signal | Vorgehen |
|---|---|
| Ergebnis kann nicht ausgegeben werden | B2:F7 freimachen, ohne die ursprünglichen Eingaben zu löschen |
| Schlüssel fehlt oder `401` | Seitenleiste öffnen und gespeicherten Schlüssel prüfen |
| `402` | Kontingent und Guthaben prüfen; das Script kauft keine Einheiten |
| `429` | Vor einem manuellen neuen Versuch warten und gleichzeitige Aufrufe reduzieren |
| Zeitlimit überschritten | Bereich verkleinern: Google begrenzt eine benutzerdefinierte Funktion auf 30 Sekunden |

Ein fehlgeschlagener Aufruf ist keine ungültige IBAN. Berücksichtigen Sie vor einem neuen Versuch die bereits erfolgten Aufrufe. Für grössere wiederkehrende Aufgaben helfen die [Integrationsrezepte](/de/docs/recipes), einen Ablauf mit vollständigen Antworten zu wählen. Der [Quellcode des Scripts](https://github.com/cammac-creator/ibanforge/tree/main/integrations/sheets) ist einsehbar.
