*Aktualisiert am 4. November 2026.*

Eine IBAN-Prüfungs-API hilft Softwareteams, die Struktur von Bankverbindungen zu prüfen und Referenzdaten zu Banken abzurufen. Ein sinnvoller Einsatzpunkt liegt oft **vor der Übernahme in die Buchhaltung**: bei der Lieferantenanlage, der Rechnungserfassung oder der Vorbereitung einer Migration.

IBANforge bestätigt **weder die Existenz oder Offenheit eines Kontos noch die Identität seines Inhabers**. Es führt keine Zahlungen aus. Die fünf Abläufe unten sind Integrationsbeispiele, keine Kundenberichte oder gemessenen Einsparungen.

## 1. ERP-Migration: den Lieferantenstamm vor dem Import prüfen

**Für:** ERP-Integratoren und Teams beim Wechsel der Buchhaltungssoftware.

Eine Migrationsdatei kann fehlende BICs, falsch erfasste IBANs und als zurückgezogen markierte Bankleitzahlen enthalten. Eine Prüfziffer unterscheidet diese Fälle nicht. Senden Sie eine Stichprobe an den [Batch-Endpunkt](/de/docs/iban-batch), behalten Sie die Originaldatensätze und erstellen Sie eine separate Prüfdatei.

Lesen Sie `valid` für die Struktur, `bank_code_check` für den Nachweis zur Bankleitzahl und `bic.authoritative` für die Aussagekraft der IBAN-BIC-Zuordnung. Ein nicht verfügbares Register lässt eine Frage offen. Es macht das Konto weder ungültig noch erlaubt es, einen vorhandenen BIC zu überschreiben.

**Einstieg:** Die [Anleitung zur ERP-Migration](/de/blog/2026-09-02-missing-bank-details-before-an-erp-migration) enthält ein Python-Beispiel zum Herunterladen. Für eine einmalige Datei ohne Integration gibt es die [Dateiprüfung](/de/audit).

## 2. Rechnungserfassung: das OCR-Ergebnis prüfen

**Für:** Anbieter von Dokumentenverarbeitung und Kreditorensoftware.

Prüfen Sie eine aus einer Rechnung extrahierte IBAN, bevor Sie sie für den Lieferantendatensatz vorschlagen. IBANforge prüft den übermittelten Wert; es liest weder die Rechnung noch beurteilt es deren Echtheit.

Eine korrekte Prüfziffer schliesst Rechnungsbetrug nicht aus: Auch ein Angreifer kann eine gültige IBAN angeben. Behalten Sie eine gesonderte Freigabe für Kontowechsel bei, über einen Ihrer Organisation bereits bekannten Kontaktkanal. Ersetzen Sie die Bankverbindung nicht allein deshalb, weil die neue Nummer die Prüfung besteht.

Nutzen Sie die [Batch-Prüfung](/de/docs/iban-batch) für mehrere Kandidaten. Erhalten Sie die Zuordnung zum Quelldokument. Ein HTTP-Fehler bedeutet eine nicht abgeschlossene Prüfung, keinen erfolgreichen Nachweis.

## 3. Lieferantenanlage: Bankdaten und Identität trennen

**Für:** Einkaufsplattformen, Lieferantenportale und Buchhaltungsprodukte.

Geben Sie bei der Eingabe ein konkretes Ergebnis zurück: ungültiges Format, durch ein Register identifizierte Bank, abgeleitete Zuordnung oder nicht verfügbare Abfrage. Zeigen Sie Quelle und Datenstand, wenn Referenzdaten eine Entscheidung unterstützen.

`checks.account_exists` und `checks.payee_name` bleiben `not_checked`. `bic.bank_name` nennt die Bank, nicht den Kontoinhaber. Weder dieser Name noch die Klassifizierung des Emittenten bestätigt die Identität des Lieferanten.

Ein Abgleich zwischen Name und Konto benötigt einen gesonderten Dienst, etwa Verification of Payee des Zahlungsdienstleisters. Siehe [IBAN-Prüfung und VoP im Vergleich](/de/docs/vop).

## 4. Zahlungsformulare: verständliche Rückmeldung geben

**Für:** Lohn-, Abrechnungs- und Zahlungssoftware.

Prüfen Sie die IBAN auf Ihrem Server beim Absenden des Formulars. Der API-Schlüssel bleibt auf dem Server und gehört nicht in das JavaScript des Browsers. Für reine Strukturprüfungen ohne Referenzdaten kann die [freie Bibliothek](https://github.com/cammac-creator/iban-core) ausreichen.

Dieses Node.js-Beispiel führt eine authentifizierte Prüfung aus. Stellen Sie `IBANFORGE_API_KEY` in der Serverumgebung bereit:

```javascript
const key = process.env.IBANFORGE_API_KEY;
if (!key) throw new Error("IBANFORGE_API_KEY manque");

const response = await fetch("https://api.ibanforge.com/v1/iban/validate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${key}`,
  },
  body: JSON.stringify({ iban: "DE89370400440532013000" }),
  signal: AbortSignal.timeout(15000),
});
if (!response.ok) throw new Error(`Validation indisponible : HTTP ${response.status}`);
const result = await response.json();
console.log(result.valid, result.bank_code_holder, result.checks);
```

`valid: true` beschreibt Struktur und Prüfziffer der IBAN. Lesen Sie auch die gesonderten Ergebnisse zu nationalen Prüfziffern und zur Bankleitzahl. Die SEPA-Zugehörigkeit eines Landes beweist nicht die Erreichbarkeit einer bestimmten Bank oder eines Kontos; die [API-Referenz](/de/docs/iban-validate) erklärt die Angaben auf Bankebene. Keine dieser Prüfungen garantiert die Ausführung einer Zahlung.

## 5. KI-Werkzeuge: Nachweise an den Arbeitsablauf übergeben

**Für:** Entwickler, die Assistenten um Finanzdaten-Werkzeuge erweitern.

Die [MCP-Schnittstelle](/de/docs/mcp) stellt IBAN-Prüfung und BIC-Suche für kompatible Clients bereit. Erklären Sie anhand des strukturierten Ergebnisses, welche Prüfungen bestanden, abgeleitet oder nicht durchgeführt wurden. Quellenhinweise und Einschränkungen bleiben in der dargestellten Antwort erhalten.

Ein Assistent darf `valid: true` nicht als Freigabe verstehen, die Bankverbindung eines Lieferanten zu ändern oder Geld zu senden. Diese Freigaben gehören in die Fachanwendung und deren Kontrollen.

## Den passenden Einstieg wählen

- **Eine Nummer:** eine Antwort im [Playground](/de/playground) ansehen.
- **Eine Lieferantendatei:** die Vorschau der [Dateiprüfung](/de/audit) verwenden.
- **Ein wiederkehrender Ablauf:** mit den [Integrationsrezepten](/de/docs/recipes) und dem [Leitfaden für Softwareanbieter](/de/vendors) beginnen.

Kontingente der API-Schlüssel und vorausbezahlte Pakete stehen auf der [Preisseite](/de/pricing). Der Batch-Endpunkt benötigt einen Schlüssel oder einen unterstützten Zahlungsmechanismus; der Test ohne Schlüssel für einzelne IBANs ist ein eigener Einstieg. Die [Startanleitung](/de/docs/onboarding) beschreibt die aktuellen Möglichkeiten.
