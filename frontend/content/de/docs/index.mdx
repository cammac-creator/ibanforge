# IBANforge API

IBANforge prüft die **Struktur einer IBAN** und sucht **verfügbare Bankreferenzen**: Institut, BIC und Herkunft der Information. Die Ergebnisse unterscheiden einen bestätigten Code, einen im aussagekräftigen Register fehlenden Code und unzureichende oder nicht verfügbare Referenzen. Die [Abdeckung nach Quelle](/de/docs/data-sources) erklärt diese Unterschiede.

[Postman-Sammlung für die ersten Aufrufe herunterladen](/integrations/ibanforge-postman-premiers-appels-4036d71e6896.json)

Der Dienst bestätigt weder die Existenz des Kontos noch dessen Inhaber. Sanktionsindikatoren betreffen das Institut und das Land, nicht den genannten Zahlungsempfänger. Ein gültiges Ergebnis ist keine Zahlungsfreigabe.

## Erster Aufruf ohne Schlüssel

```bash
curl --silent --show-error --include \
  --request POST https://api.ibanforge.com/v1/iban/validate \
  --header 'Content-Type: application/json' \
  --data '{"iban":"CH10 0023 0000 0000 1234 5"}'
```

Diese IBAN ist ein Dokumentationsbeispiel, kein Zahlungsauftrag. Der REST-Test umfasst **25 Validierungen pro ISO-Woche in UTC und Quelladresse**, nur auf dieser Route. Der Block `trial` nennt Restkontingent und Rücksetzungszeit. In einem gemeinsam genutzten Netzwerk kann das Kontingent bereits verbraucht sein; `402 trial_exhausted` ist kein IBAN-Befund.

Die [ersten Schritte](/de/docs/onboarding) erklären den wiederverwendbaren Schlüssel, den ersten Stapel und Fehler. Ein per E-Mail-Code beanspruchter kostenloser Schlüssel bietet 200 Anfragen pro Monat. Ohne Adresse beginnt er normalerweise mit 25 monatlichen Anfragen; lesen Sie immer `monthly_limit` und eine mögliche `notice`.

## Das Ergebnis auf mehreren Ebenen lesen

- **HTTP**: Wurde die Anfrage verarbeitet? Eine Kontingentablehnung bedeutet keine ungültige IBAN.
- **`valid` und `checks`**: Format, Prüfsumme und tatsächlich ausgeführte Prüfungen. `not_checked` bedeutet nicht `pass`.
- **`bank_code_check` und `bic`**: Registerbefund, Aussagekraft, Quelle und Stand. Ein fehlender Eintrag in einer Teilquelle beweist keine Nichtzuteilung.
- **Grenzen auf Kontoebene**: Existenz des Kontos, Kontoinhaber und Sanktionen des Empfängers werden damit nicht geprüft.

Die [Validierungsreferenz](/de/docs/iban-validate) erklärt die Felder, die [Fehlerreferenz](/de/docs/errors) die Ablehnungen. Halten Sie ursprüngliche Bankverbindungen und Vorschläge in Ihrer Integration getrennt.

## Wichtige Routen

HTTPS-Basis: `https://api.ibanforge.com`. Den vollständigen Vertrag finden Sie in der [OpenAPI-Referenz](/de/openapi) und der [Postman-Collection](/ibanforge-postman.json).

Die folgenden x402-Preise gelten nur bei gewählter Zahlung pro Aufruf. Sie werden nicht zusätzlich zum REST-Test oder zu Aufrufen innerhalb des Schlüsselkontingents oder Prepaid-Guthabens berechnet. Siehe [x402](/de/docs/x402) für die Zahlung und [Preise](/de/pricing) für aktuelle Angebote.

| Route | Zweck | Zugang | x402 |
|---|---|---|---|
| [`POST /v1/iban/validate`](/de/docs/iban-validate) | Struktur und Referenzen für eine IBAN | Test ohne Schlüssel auf dieser Route, danach Schlüssel oder autorisierter kostenpflichtiger Zugang | 0.005 USDC |
| [`POST /v1/iban/batch`](/de/docs/iban-batch) | Bis zu 100 IBAN, ein Ergebnis je Eingabe | Eine Kontingenteinheit pro IBAN | 0.002 USDC / IBAN |
| [`GET /v1/bic/:code`](/de/docs/bic-lookup) | BIC-Suche | Schlüssel oder autorisierter kostenpflichtiger Zugang | 0.003 USDC |
| [`GET /v1/ch/clearing/:iid`](/de/docs/ch-clearing) | Schweizer Clearing-Referenz | Schlüssel oder autorisierter kostenpflichtiger Zugang | 0.003 USDC |
| [`POST /v1/iban/compliance`](/de/docs/compliance) | Indikatoren zu Institut und Land | Schlüssel oder autorisierter kostenpflichtiger Zugang; kein Empfänger-Screening | 0.02 USDC |
| [`GET` oder `POST /v1/iban/format`](/de/openapi) | Struktur und Prüfsumme ohne Banksuche | Kostenlos, ohne Schlüssel | 0 |
| [`GET` oder `POST /v1/reference/validate`](/de/docs/swiss-qr-iban) | Prüfsumme unterstützter Zahlungsreferenzen | Kostenlos, ohne Schlüssel | 0 |
| [`POST /v1/address/check`](/de/docs/structured-addresses) | Adressformat nach gewähltem Schema und belegten Regeln | Kostenlos, ohne Schlüssel | 0 |
| [`POST /v1/ch/qr-bill/check`](/de/docs/swiss-qr-iban) | Struktur des Inhalts einer Schweizer QR-Rechnung | Kostenlos, ohne Schlüssel | 0 |
| [`POST /v1/audit/upload`](/de/audit) | Prüfung einer CSV- oder Excel-Datei | Kostenlose Vorschau; vollständiger Bericht zum angezeigten Preis | Eigener Dateipreis |
| [`GET /v1/demo`](/de/docs/onboarding) | Öffentliche Beispielantworten | Kostenlos; prüft keinen Schlüssel | 0 |
| [`GET /health`](https://api.ibanforge.com/health) | Öffentlicher Dienststatus | Kostenlos | 0 |

Prepaid-Pakete: **1.000 Credits = 4 $; 5.000 = 20 $; 25.000 = 80 $**. Credits verfallen nicht; eine Validierung oder Suche kostet einen Credit, ein Batch einen je IBAN. Kartenzahlung und USDC stehen unter [Preise](/de/pricing). Die Dateiprüfung hat einen eigenen, von der Dateigröße abhängigen Preis, der mit der kostenlosen Vorschau angezeigt wird; diese Aufrufpreise enthalten ihn nicht.

[Preise](/de/pricing) und [Zugangsgrenzen](/de/docs/api-keys) beschreiben die Angebote. Eine `402`-Antwort erklärt die Möglichkeiten; sie ermächtigt eine Automatisierung weder zum Kauf von Guthaben noch zu einer Zahlung.
