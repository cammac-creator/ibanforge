# MCP-Integration

IBANforge liefert einen offiziellen **MCP-Server** für KI-Agenten: [`ibanforge-mcp`](https://www.npmjs.com/package/ibanforge-mcp) auf npm, plus einen gehosteten Endpoint ganz ohne Installation. Claude, Cursor oder jeder MCP-kompatible Client kann IBANs validieren, BICs auflösen, Schweizer Clearing-Nummern prüfen und eine Compliance-Vorprüfung als Tool-Aufrufe ausführen.

## Was ist MCP?

Das [Model Context Protocol](https://modelcontextprotocol.io/) ist ein offener Standard, der KI-Assistenten die Nutzung externer Tools erlaubt. Statt den Nutzer API-Ergebnisse kopieren zu lassen, ruft der Agent das Tool direkt auf und erhält strukturierte Daten zurück.

## Option 1 — das npm-Paket (stdio)

**Claude Desktop** — IBANforge in die Konfigurationsdatei eintragen:

**macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

**Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "ibanforge": {
      "command": "npx",
      "args": ["-y", "ibanforge-mcp"],
      "env": { "IBANFORGE_API_KEY": "ifk_ihr_schluessel" }
    }
  }
}
```

**Claude Code** — ein einziger Befehl:

```bash
claude mcp add ibanforge -e IBANFORGE_API_KEY=ifk_ihr_schluessel -- npx -y ibanforge-mcp
```

Der Schlüssel ist optional und kostenlos — 25 Anfragen/Monat ohne E-Mail. [Generieren Sie einen](/docs/api-keys) per POST ohne Body und senden Sie `Authorization: Bearer ifk_...`. Mit einem Code per E-Mail beanspruchen Sie denselben Schlüssel für 200/Monat, ohne Kreditkarte.

Nach dem Speichern den Client neu starten. Das npm-Paket bietet **13 Tools**, der entfernte HTTP-Server **11**. Die zwei Datei-Audit-Tools sind nur im npm-Paket verfügbar. Siehe [Katalog nach Transport](/agents#mcp-quickstart).

## Option 2 — der gehostete Endpoint (nichts zu installieren)

```
https://api.ibanforge.com/mcp
```

Streamable-HTTP-Transport, **25 kostenlose Tool-Aufrufe pro Woche und Quelladresse**, ganz ohne Schlüssel (ISO-Woche in UTC, Neustart montags um 00:00 UTC; ein Batch zählt einen Aufruf pro IBAN; getrennt vom REST-Test ohne Schlüssel): der schnellste Weg für einen Agenten, die Daten zu prüfen, bevor Sie sich festlegen. Für dauerhafte Nutzung den kostenlosen Schlüssel mit jeder Anfrage senden (siehe unten) oder das npm-Paket damit betreiben.

### Mit Ihrem Schlüssel

Der gehostete Endpoint liest einen IBANforge-Schlüssel aus einem Header der Anfrage, `Authorization: Bearer ifk_…` oder `X-API-Key: ifk_…`, dieselben zwei Header wie die REST-API. Die Tool-Aufrufe werden dann genau wie REST-Aufrufe auf diesen Schlüssel gezählt: sein eigenes Kontingent, eine Einheit pro Aufruf, eine pro IBAN in einem Batch, nichts für die kostenlosen Tools, und dieselben Ablehnungen. Das schlüssellose Kontingent oben wird nicht mehr genutzt. Ein Schlüssel in der Adresse (`?api_key=`) wird nicht gelesen. Ist der Schlüssel unbekannt, widerrufen oder aufgebraucht, antwortet das Tool mit der Meldung der REST-API für diesen Schlüssel und fällt nie auf das schlüssellose Kontingent zurück.

**Claude Code:**

```bash
claude mcp add --transport http ibanforge https://api.ibanforge.com/mcp --header "Authorization: Bearer ifk_ihr_schluessel"
```

**Claude und Claude Desktop** (benutzerdefinierter Connector, Schritte unten): Unter **Request headers** den Header `Authorization` mit dem Wert `Bearer ifk_ihr_schluessel` hinzufügen. Die Seite von Claude, gelesen am 7. Oktober 2026, beschreibt dieses Feld für feste Zugangsdaten wie API-Schlüssel. In Team und Enterprise teilen sich dann alle, die den Connector nutzen, diesen Schlüssel. *Von uns nicht ausprobiert.*

**ChatGPT:** Die [Seite von OpenAI zur Authentifizierung](https://developers.openai.com/plugins/build/auth), gelesen am 7. Oktober 2026, sagt, dass ChatGPT sich mit OAuth oder ohne Authentifizierung mit einem MCP-Server verbindet und keinen eigenen API-Schlüssel übergeben kann. In ChatGPT bleibt der gehostete Endpoint daher beim schlüssellosen Kontingent; Ihr Schlüssel dient der REST-API oder dem npm-Paket in einem anderen Client.

**Gemini:** von uns nicht geprüft.

### Als Connector in einem Chat-Assistenten hinzufügen

In einem Chat-Assistenten wird die Adresse oben zu einem *benutzerdefinierten Connector*: Der Assistent ruft die MCP-Tools dann selbst auf, statt eine Antwort zu erraten, die er nicht abrufen kann.

**Ein Connector ohne Schlüssel greift auf dasselbe schlüssellose Kontingent zu wie jeder andere Aufrufer**, gezählt pro Quelladresse. In Claude gehen die Aufrufe eines Connectors von der Cloud von Anthropic aus, nicht von Ihrem Gerät (offizielle Seite unten, Abschnitt „Network requirements“): Dieses Kontingent wird also mit anderen Nutzern geteilt und kann schon aufgebraucht sein, wenn Sie beginnen. Andere Assistenten: von uns nicht geprüft. Mit Ihrem eigenen Schlüssel wird der Connector auf diesen Schlüssel gezählt: siehe *Mit Ihrem Schlüssel* oben (Claude nimmt ihn als Header der Anfrage, ChatGPT sendet keinen). Ein POST auf `https://api.ibanforge.com/v1/keys/generate` ohne Body liefert einen Schlüssel, ohne E-Mail.

## Verfügbare Tools

Die folgenden JSON-Objekte sind **Tool-Argumente**, die Ihr MCP-Client übergibt. Es sind Dokumentationsbeispiele; sie belegen nicht, dass ein Konto existiert. Für einen kostenlosen ersten Test auf beiden Transportwegen verwenden Sie `validate_payment_reference` **ohne IBAN**. Lesen Sie `tools/list` in Ihrer Sitzung: installiertes Paket und gehosteter Server können sich unabhängig weiterentwickeln.

### validate_iban

Prüft Aufbau und Prüfsumme der IBAN und liefert verfügbare Bankinformationen. Lesen Sie `valid`, `bank_code_check` und `bic` getrennt. Ein fehlender BIC, eine nicht verfügbare Quelle oder eine Standardklassifizierung müssen eingeordnet werden; sie beweisen weder Kontoschliessung noch Betrug. Erhalten Sie `source`, `as_of`, `basis` und `authoritative`, soweit vorhanden. [Ergebnis lesen](/de/docs/iban-validate).

```json
{ "iban": "CH1000230000000012345" }
```

### batch_validate_iban

Nimmt 1 bis 100 IBANs an und liefert ein Objekt mit `results`, `count` und `valid_count`. Die Ergebnisse folgen der Eingabereihenfolge. Erhalten Sie diese Reihenfolge und Ihre Zeilenkennungen; das Tool schreibt keine Lieferantendatei um. Schlüssel und Verbrauch richten sich nach dem gewählten Transportweg. [Stapelprüfung](/de/docs/iban-batch).

```json
{ "ibans": ["CH1000230000000012345", "DE89370400440532013000"] }
```

### lookup_bic

Sucht ein Institut anhand eines bereits bekannten BIC. **Das Eingabefeld heisst `bic`, nicht `code`**, sowohl im npm-Paket als auch beim gehosteten Server. `valid_format` beschreibt das Format; `found` sagt, ob ein Eintrag gefunden wurde. Name, LEI und Adresse können fehlen oder unterschiedliche Datumsangaben tragen. [BIC-Anleitung](/de/docs/bic-lookup).

```json
{ "bic": "UBSWCHZH80A" }
```

### lookup_ch_clearing

Sucht eine Schweizer oder liechtensteinische IID / BC-Nummer. Lesen Sie `found`, verfügbare Instituts- und Teilnahmeinformationen sowie deren Herkunft. Eine `qr_iid` kann aus dem Register stammen oder vom Hauptsitz übernommen sein: erhalten Sie `qr_iid_basis`. Eine IID im QR-Bereich beweist nicht, dass das Konto existiert. [Clearing-Anleitung](/de/docs/ch-clearing).

```json
{ "iid": "230" }
```

### check_compliance

Ergänzt das Validierungsergebnis um Bank- und Länderindikatoren. Lesen Sie Abfragestatus (`screened`, `bank_screened`), `null`-Werte, `flags` und Quelldaten vor dem Score. Der Score ersetzt keine Prüfung des Vorgangs. Ein Bankeintrag im VoP-Register ist keine Prüfung des Empfängernamens; das Bankenscreening prüft nicht den Begünstigten. [Kontrollen verstehen](/de/docs/compliance).

```json
{ "iban": "CH1000230000000012345" }
```

### validate_payment_reference

Prüft eine RF/SCOR-, QRR-, OGM/VCS- oder viitenumero-Referenz. **Ohne IBAN ist dieser Aufruf auf beiden Transportwegen kostenlos.** Beispiel für den ersten Test:

```json
{ "reference": "RF18539007547034" }
```

Eine optionale IBAN ergänzt die Prüfung der Kombination. **Unterschied der Transportwege:** Der gehostete HTTP-Server prüft diese Kombination kostenlos; das npm-Paket 1.9.0 ruft dafür `POST /v1/iban/validate` zu dessen Zugangsbedingungen auf. Das folgende Beispiel ist daher nicht in jedem Client kostenlos. `valid` und `pairing` sind unabhängig. Bei KID und OCR bedeutet `valid: null`, dass die Konfiguration des Gläubigerkontos benötigt wird, nicht dass die Referenz ungültig ist.

```json
{ "reference": "210000000003139471430009017", "iban": "CH4431999123000889012" }
```

### check_postal_address

Prüft kostenlos Formatregeln für `sps`, `hvps_plus` oder `fedwire`. Erhalten Sie die Quelle jedes Befunds und das Feld `note`; `not_applicable` ist keine bestandene Prüfung. Das Tool prüft nicht, ob eine Strasse existiert. Bei CH/LI beschreibt der separate Block `postcode_locality` den Abgleich von Postleitzahl und Ort, soweit möglich. [Regeln und Termine](/de/docs/structured-addresses).

```json
{ "scheme": "sps", "address": { "strt_nm": "Bahnhofstrasse", "bldg_nb": "45", "pst_cd": "8001", "twn_nm": "Zurich", "ctry": "CH" } }
```

### check_swiss_qr_bill

Prüft kostenlos den mit `SPC` beginnenden Text einer Schweizer QR-Rechnung: Aufbau, IBAN, Referenz und Kombination, Betrag, Währung und Adressen. Es decodiert kein Bild. `valid` beschreibt den geprüften Inhalt, nicht das Konto oder die Annahme durch eine Bank. `proposed_structured` bleibt ein zu prüfender Vorschlag. Erhalten Sie die Quellen der `findings`; für QR-Rechnungen und Zahlungsaufträge gelten unterschiedliche Termine. [QR-Rechnungsanleitung](/de/docs/swiss-qr-iban). Die Namen im folgenden Payload sind erfunden.

Der Adresstyp K ist in einer QR-Rechnung seit dem 21.11.2025 nicht mehr zulässig (SIX, IG QR-Rechnung 2.3). Die Banken garantieren die Zahlung einer solchen QR-Rechnung nur bis Ende September 2026 (UBS: 30.09.2026; ZKB: längstens bis Ende September 2026). Eine QR-Rechnung mit Typ K kann daher bei der Zahlung abgewiesen werden: Stellen Sie sie mit Typ S neu aus. Ab dem 14.11.2026 verlangen die Swiss Payment Standards in einem Zahlungsauftrag eine strukturierte oder hybride Adresse, mit Ort und Land in eigenen Feldern. Das SIC-System prüft die Adressen nicht: Jede Bank entscheidet selbst. Manche akzeptieren Inlandzahlungen vorläufig weiter; eine SEPA- oder Auslandzahlung ohne Ort kann abgewiesen werden. Erfassen Sie auch die Daueraufträge und Vorlagen neu, die aus einer QR-Rechnung mit Typ K übernommen wurden.

```json
{ "payload": "SPC\n0200\n1\nCH4431999123000889012\nS\nSociete Alpha\nRue du Lac\n1268\n2501\nBiel\nCH\n\n\n\n\n\n\n\n1949.75\nCHF\nS\nSociete Beta\nMarktgasse\n28\n9400\nRorschach\nCH\nQRR\n210000000003139471430009017\nOrder 15.06.2026\nEPD" }
```

### audit_creditor_file

Prüft eine gesamte Kreditoren-/Lieferantendatei (CSV oder XLSX) zeilenweise: IBAN-Struktur und Prüfziffer, Bankcode gegen das Nationalregister, Bankname und BIC, SEPA-Erreichbarkeit und Emittententyp, plus Prüfungen, die ein einzelner IBAN-Aufruf nicht leisten kann, weil sie die ganze Datei brauchen — doppelte IBANs, der von der Datei mitgeführte BIC gegen den vom Register abgeleiteten BIC, Adressland gegen IBAN-Land, und die im Bericht beschriebenen Adressprüfungen. Liefert **nur eine kostenlose Vorschau** (maskierte IBANs, Summenzahlen, bis zu 20 Zeilen) — der vollständige annotierte `.xlsx`-Bericht ist eine kostenpflichtige Leistung (149 $ bis 5'000 Zeilen, 349 $ bis 20'000), beglichen über eine einmalige Stripe-Checkout-Session, nie automatisch bezahlt. Mit `checkout: true` wird zusätzlich die Checkout-URL zurückgegeben, die ein Mensch öffnet. Die Datei base64-kodiert als `file_base64` senden; Dateien über 5 MB werden lokal abgelehnt, vor jedem Netzwerkaufruf: darüber sprengt die Base64-Nutzlast den stdio-Kanal, und der Agent verliert seine Verbindung, statt einen Fehler zu erhalten. Die HTTP-Route nimmt bis zu 10 MB — für eine grosse Datei diesen Weg nehmen.

Das Beispiel enthält eine erfundene Zeile. Base64 verschlüsselt die Datei nicht: Ihr Inhalt wird an den Dienst übertragen. Verwenden Sie nur Daten, die Sie übermitteln dürfen; eine maskierte Vorschau bedeutet nicht, dass die Datei lokal geblieben ist. [Dateiprüfung](/de/vendors).

```json
{ "file_base64": "Tm9tO0lCQU4KU29jaWV0ZSBBbHBoYTtDSDEwMDAyMzAwMDAwMDAwMTIzNDUK", "filename": "kreditoren.csv", "lang": "de" }
```

### audit_status

Liest den Status des von `audit_creditor_file` gelieferten Jobs. Die folgende Kennung ist erfunden: ersetzen Sie sie durch die Kennung Ihrer Antwort. Eine optionale `session_id` stammt aus der Rückleitung Ihres eigenen Checkouts; erfinden Sie sie nicht. Dieses Tool führt keine Zahlung aus. Der Download hängt vom Jobstatus ab.

```json
{ "job": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" }
```

*`audit_creditor_file` und `audit_status` gibt es vorerst nur im npm-Paket (Option 1) — noch nicht auf dem gehosteten HTTP-Endpoint (Option 2).*

### send_feedback

Sendet eine Rückmeldung an die Betreiber: Diese Aktion schreibt eine Nachricht und ist kein Verbindungstest. `error_type` und `notes` sind erforderlich; keine Schlüssel, Kundendateien oder sensiblen Bankdaten einfügen. Das Tool ist kostenlos und hat eigene Schutzmassnahmen gegen Missbrauch. Anfragen und Erstattungen richten sich nach den [Nutzungsbedingungen](/de/terms). Das folgende Beispiel ist eine anzupassende Vorlage, kein beobachteter Fehler.

```json
{"error_type": "stale_bic", "notes": "Durch betroffenen BIC, öffentliche Quelle und erwartetes Ergebnis ersetzen.", "endpoint": "/v1/iban/validate"}
```

### request_api_key

Einen Schlüssel ohne E-Mail anfordern: Das Tool liefert einen Link, den eine Person im Browser öffnet und genehmigt. Auf beiden Transporten verfügbar.

Der Schlüssel schaltet die Sitzung, die ihn angefordert hat, nicht frei: Er wirkt, sobald er in der Konfiguration des Clients steht, nach einer neuen Verbindung. Wohin damit:

- **Claude Code mit dem npm-Paket:** die `config_line`, die `poll_api_key` liefert, ein Befehl `claude mcp add … -e IBANFORGE_API_KEY=…`.
- **Claude Code am gehosteten Endpoint:** `--header "Authorization: Bearer ifk_…"` (siehe *Mit Ihrem Schlüssel*).
- **Claude und Claude Desktop:** die **Request headers** des benutzerdefinierten Connectors, oder `IBANFORGE_API_KEY` in `claude_desktop_config.json` mit dem npm-Paket (Option 1).
- **ChatGPT:** nirgends an einem Connector, der keinen Schlüssel sendet; der Schlüssel dient der REST-API.
- **Jeder HTTP-Client:** die REST-API, mit `Authorization: Bearer ifk_…`.

### poll_api_key

Den genehmigten Schlüssel mit dem `device_code` von `request_api_key` abholen. Er wird nur einmal ausgegeben: bewahren Sie ihn auf und hinterlegen Sie ihn, wie die Liste oben sagt. Auf beiden Transporten verfügbar.

## Antworten lesen, ohne ein Urteil zu erfinden

Der MCP-Client erhält eine Hülle mit `content` und bei strukturierten Antworten `structuredContent`. Prüfen Sie zuerst, ob der Aufruf fehlgeschlagen ist. `isError: true` oder ein Protokollfehler ist kein `valid: false`: Ein verwertbares fachliches Ergebnis ist dann nicht gewährleistet.

| Situation | Diese Unterscheidung erhalten |
|---|---|
| `valid: false` in einer erfolgreichen Antwort | Die IBAN-Prüfung ist fehlgeschlagen; Details lesen. |
| `bic: null`, `unknown` oder nicht verfügbare Quelle | Unvollständiges oder unbekanntes Ergebnis; Status beibehalten. |
| Ablehnung 401, 402 oder 429 | Zugangs-, Kontingent- oder Frequenzproblem; Meldung und gegebenenfalls `retry_after` lesen. |
| Zeitüberschreitung, Netzwerkfehler oder unlesbare Antwort | Kein vollständiges Ergebnis; die Anfrage kann den Server erreicht haben. |

Das npm-Paket 1.9.0 kann bei einem mit 402 abgelehnten Versuch ohne Schlüssel eine **eingeschränkte Formatprüfung** liefern: `_degraded: true` und `_scope: "format_only"`. Das ist keine vollständige Bankauflösung. Ein konfigurierter, aber abgelehnter Schlüssel löst diesen Rückfall nicht aus. Das Paket signiert keine x402-Zahlungen und erstellt keinen neuen Schlüssel zur Fortsetzung.

`next_steps` enthält aus dem Ergebnis berechnete Empfehlungen. Erhalten Sie gegebenenfalls `code`, `do` und `because` und prüfen Sie die genannten Felder. Diese Empfehlungen erlauben weder eine Zahlung noch eine Änderung von Bankdaten oder ein Urteil über den Kontoinhaber. Fehlende Quellen bleiben fehlende Quellen. [Fehler und Zugang](/de/docs/errors).

Die Codes `bank_code_not_allocated`, `modulus_check_failed` und `national_check_digits_failed` kennzeichnen eine blockierende Prüfung, die vor der Weiterverarbeitung zu klären ist. Sie betreffen die Zuteilung des Bankcodes, die britische Kombination aus Sort Code und Kontonummer beziehungsweise die nationale Prüfziffer. `national_check_digits_suspect` verlangt eine Bestätigung der Nummer, ohne sie für ungültig zu erklären; `verify_payee_name` verlangt eine separate Prüfung des Empfängernamens. Ein fehlender Code erlaubt keine Zahlung.

## Ein nachvollziehbarer erster Test

> Prüfe nur die Dokumentationsreferenz `RF18539007547034` mit `validate_payment_reference`, ohne IBAN. Nenne das erkannte Schema, `valid` und die erhaltene Quelle. Wenn der Aufruf fehlschlägt, erkläre den Fehler, ohne ein Ergebnis zu erfinden.

Rufen Sie für einen Bankauflösungstest anschliessend `validate_iban` mit dem Beispiel aus dessen Abschnitt auf. Bitten Sie den Assistenten, die erhaltenen Werte und ihre Herkunft einschliesslich unbekannter Felder wiederzugeben. Diese Seite garantiert weder einen Banknamen noch ein Registerergebnis.

## Funktioniert gut mit

**[PayQR](https://qr.cz-agents.dev)** — `npx -y @czagents/payqr`, gehostetes MCP `https://payqr.cz-agents.dev/mcp`, Registry `dev.cz-agents/payqr`. Erzeugt und prüft selbst einen europäischen Zahlungs-QR aus einer IBAN und den Zahlungsdetails: SPAYD für CZ/SK-Konten, EPC/GiroCode (nur EUR) für andere SEPA-Konten; EPC verlangt `recipient_name`. PayQR validiert die IBAN-Prüfziffer, verifiziert aber weder Kontoinhaberschaft noch Empfängernamen und erzeugt keine nativen Schweizer QR-Rechnungen — Registerprüfung, VoP-Bereitschaft und Risikoindikatoren sind genau das, was IBANforge obendrauf liefert.

## Unterstützte Clients

- **Claude Desktop** und **Claude Code** — natives MCP
- **Cursor** und **Continue.dev** — über deren MCP-Konfiguration
- **n8n** — besser den dedizierten [Community-Node](/docs/recipes) nutzen
- **Eigene Agenten** — jede App mit dem MCP SDK

## Hinweise

- Das npm-Paket sendet die Argumente an die IBANforge-API. Es ist kein Offline-Dienst für Bankdaten.
- Quellen unterscheiden sich in Datum und Abdeckung. Lesen Sie die tatsächlich gelieferten Datumsangaben; ein aktueller Aufruf kann eine ältere Quelle abfragen.
- Die Schemas von `tools/list` beschreiben die verbundene Version. Die beiden Audit-Tools gibt es nur im npm-Paket.
- Zugang, Preise und Fehler sind unter [API-Schlüssel](/de/docs/api-keys), [Preise](/de/pricing) und [Fehlerhilfe](/de/docs/errors) erläutert.
