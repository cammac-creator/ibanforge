# Rezepte — IBAN validieren in Ihrem Stack

Jedes Rezept nutzt denselben Endpunkt: `POST /v1/iban/validate` — Struktur + Prüfziffer, ausgebende Bank (BIC), Bankcode-Prüfung gegen das Nationalregister, EMI/vIBAN-Klassifikation und SEPA/VoP-Erreichbarkeit. Zuerst ein kostenloser Schlüssel (200 Anfragen/Monat, ohne Karte):

```bash
curl -X POST https://api.ibanforge.com/v1/keys/generate \
  -H "Content-Type: application/json" \
  -d '{"email": "sie@firma.com"}'
```

Die ehrliche Notiz, die in jede Integration gehört: Eine lokale Mod-97-Prüfung fängt Tippfehler — sonst nichts. Drei der vier offiziellen Beispiel-IBANs bestehen jede Prüfziffer und zeigen dennoch auf Bankcodes, die kein Register vergeben hat — [die ganze Geschichte](/blog/2026-08-06-example-ibans-unallocated-bank-codes). Die Registerprüfung ist der Teil, der lokal unmöglich ist.

## Python

Mit dem offiziellen SDK (`pip install ibanforge`):

```python
from ibanforge import IBANforge

client = IBANforge(api_key="ifk_ihr_schluessel")
result = client.validate("DE89370400440532013000")
print(result["valid"], result["bic"]["code"], result["bank_code_check"]["status"])
# True COBADEFFXXX verified
```

Oder schlicht `requests`:

```python
import requests

r = requests.post(
    "https://api.ibanforge.com/v1/iban/validate",
    json={"iban": "DE89370400440532013000"},
    headers={"Authorization": "Bearer ifk_ihr_schluessel"},
    timeout=15,
)
data = r.json()
print(data["valid"], data["bank_code_check"]["status"])  # True verified
```

## Node.js / TypeScript

Natives `fetch`, keine Abhängigkeit:

```ts
const res = await fetch("https://api.ibanforge.com/v1/iban/validate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer ifk_ihr_schluessel",
  },
  body: JSON.stringify({ iban: "DE89370400440532013000" }),
});
const data = await res.json();
console.log(data.valid, data.bic?.code, data.bank_code_check?.status);
// true COBADEFFXXX verified
```

Das offizielle SDK (`npm install @ibanforge/sdk`) kapselt denselben Aufruf mit Typen.

## PHP

Nichts über das hinaus, was PHP mitbringt:

```php
<?php
$payload = json_encode(["iban" => "DE89370400440532013000"]);
$ctx = stream_context_create(["http" => [
    "method"  => "POST",
    "header"  => "Content-Type: application/json\r\nAuthorization: Bearer ifk_ihr_schluessel",
    "content" => $payload,
    "timeout" => 15,
]]);
$data = json_decode(file_get_contents(
    "https://api.ibanforge.com/v1/iban/validate", false, $ctx), true);
echo $data["valid"] ? "gültig" : "ungültig", " — ",
     $data["bank_code_check"]["status"] ?? "n/a", PHP_EOL;
// gültig — verified
```

## Java

Das offizielle Java-SDK (Java 17 oder neuer, nur Jackson) spiegelt den TypeScript-Client Methode für Methode. Es liegt auf Maven Central: `com.ibanforge:ibanforge-sdk:1.5.0` einbinden.

```java
IBANforge client = IBANforge.builder().apiKey(System.getenv("IBANFORGE_API_KEY")).build();
IBANValidationResult r = client.validateIban("DE89 3704 0044 0532 0130 00");
System.out.println(r.valid() + " " + r.bic().code() + " " + r.bankCodeCheck().status());
```

Fehler sind unter `IBANforgeException` typisiert: `PaymentRequiredException` (402, die x402-Challenge in `accepts`), `RateLimitException`, `InvalidInputException`, `ApiException`. `client.formatIban(...)` und die anderen kostenlosen Routen brauchen keinen Schlüssel. [README und vollständige Methodentabelle](https://github.com/cammac-creator/ibanforge/tree/main/sdks/java).

## C# / .NET

Das offizielle .NET-SDK (net8.0, keine Abhängigkeit ausserhalb des Frameworks) bietet dieselben Methoden als asynchrone Aufrufe. Installieren Sie [`IBANforge.Sdk` 1.5.0 von NuGet](https://www.nuget.org/packages/IBANforge.Sdk/1.5.0):

```bash
dotnet add package IBANforge.Sdk --version 1.5.0
```

```csharp
using var client = new IBANforgeClient(new IBANforgeOptions { ApiKey = Environment.GetEnvironmentVariable("IBANFORGE_API_KEY") });
var r = await client.ValidateIbanAsync("DE89 3704 0044 0532 0130 00");
Console.WriteLine($"{r.Valid} {r.Bic?.Code} {r.BankCodeCheck?.Status}");
```

Einen eigenen `HttpClient` (IHttpClientFactory) an den Konstruktor übergeben, wenn vorhanden; die Ausnahmen spiegeln die Java- und TypeScript-Hierarchie. [README](https://github.com/cammac-creator/ibanforge/tree/main/sdks/dotnet).

## Google Sheets

Erweiterungen → Apps Script, dann eine benutzerdefinierte Funktion für `=VALIDATE_IBAN(A2)`:

```javascript
function VALIDATE_IBAN(iban) {
  const res = UrlFetchApp.fetch("https://api.ibanforge.com/v1/iban/validate", {
    method: "post",
    contentType: "application/json",
    headers: { Authorization: "Bearer ifk_ihr_schluessel" },
    payload: JSON.stringify({ iban: String(iban) }),
    muteHttpExceptions: true,
  });
  const d = JSON.parse(res.getContentText());
  return [[d.valid, d.bic ? d.bic.code : "", d.bank_code_check ? d.bank_code_check.status : ""]];
}
```

Quota im Blick behalten: ein Aufruf pro Zellauswertung. Für ganze Spalten besser der [Batch-Endpoint](/docs/iban-batch) aus einem Script (bis 100 IBANs pro Aufruf).

## n8n

Das veröffentlichte Paket [`n8n-nodes-ibanforge@0.1.1`](https://www.npmjs.com/package/n8n-nodes-ibanforge) bietet IBAN-Validierung, BIC-Suche, Schweizer Clearing und Compliance-Vorprüfungen auf Bankebene. Dieses Rezept gilt für **selbst gehostetes n8n**, mit einem Owner- oder Admin-Konto. Die Installation eines Pakets aus npm ist auf n8n Cloud nicht verfügbar; dort ist ein verifizierter Eintrag erforderlich. Siehe die [Installationsanleitung von n8n](https://docs.n8n.io/integrations/community-nodes/installation-and-management/).

1. **Settings → Community nodes → Install** öffnen und `n8n-nodes-ibanforge@0.1.1` eingeben.
2. Einen [kostenlosen API-Schlüssel](/de/docs/api-keys) beziehen (200 Anfragen/Monat, E-Mail-Adresse erforderlich, ohne Karte). In einem neuen Workflow **Manual Trigger** mit **IBANforge** verbinden und den Schlüssel in den Zugangsdaten **IBANforge API** hinterlegen.
3. **Validate IBAN** auswählen, das Dokumentationsbeispiel `DE89370400440532013000` eingeben und den Schritt ausführen.
4. Die JSON-Ausgabe prüfen: `valid` sollte für dieses Beispiel `true` sein, `bank_code_check` beschreibt das Registerergebnis und `bic` die Bank, sofern sie ermittelt werden kann. Eine abgeschlossene Operation mit diesen Feldern belegt den ersten API-Aufruf; ein grüner Verbindungstest allein genügt nicht.

In Version 0.1.1 ruft der Verbindungstest den öffentlichen Endpunkt `/v1/demo` auf, der den Schlüssel nicht prüft. Vor dem Einsatz des Workflows das tatsächliche Ergebnis von **Validate IBAN** kontrollieren. Weder ein gültiges Format noch eine identifizierte Bank belegen, dass das Konto existiert oder einem bestimmten Zahlungsempfänger gehört.

Für eine manuelle Installation die folgenden Befehle **als Benutzer des n8n-Dienstes** ausführen, gegebenenfalls in dessen Container. Anschliessend n8n neu starten:

```bash
mkdir -p ~/.n8n/nodes
cd ~/.n8n/nodes
npm install n8n-nodes-ibanforge@0.1.1
```

Der Node verarbeitet jedes eingehende Element einzeln; er hat keine Batch-Operation. Eine Liste mit 100 Elementen kann daher 100 Anfragen verbrauchen. [Details zur manuellen Installation](https://docs.n8n.io/integrations/community-nodes/installation-and-management/manual-installation/).

## Odoo

Das [öffentliche Odoo-Modul](https://github.com/cammac-creator/ibanforge-odoo/tree/18.0), Version **18.0.1.0.0** (AGPL-3), füllt BIC und Bankname aus, wenn die API sie ermitteln kann. Es benötigt **Odoo 18 mit Unterstützung für eigene Python-Module**, auf Ihrem eigenen Server oder auf Odoo.sh. [Odoo Online unterstützt diese Module nicht](https://www.odoo.com/documentation/18.0/administration/odoo_online.html). Diese Installation verwendet das Quellcode-Repository und ist nicht von einem Eintrag im Odoo Apps Store abhängig.

Auf Ihrem eigenen Odoo-Server das Repository in ein Verzeichnis Ihrer Wahl klonen:

```bash
git clone --branch 18.0 --single-branch https://github.com/cammac-creator/ibanforge-odoo.git /path/to/ibanforge-odoo
```

`/path/to/ibanforge-odoo` zur bestehenden `addons_path`-Liste von Odoo hinzufügen und die anderen Einträge beibehalten. Das Modul liegt im **Unterverzeichnis**: Das Manifest muss unter <code className="break-all">/path/to/ibanforge-odoo/ibanforge_bank_autofill/__manifest__.py</code> liegen. Alternativ nur dieses Verzeichnis `ibanforge_bank_autofill` in ein bereits konfiguriertes Addons-Verzeichnis kopieren. Die Python-Bibliothek `requests` muss in der Odoo-Umgebung verfügbar sein. Auf Odoo.sh dieses Modulverzeichnis nach der [Anleitung für eigene Module](https://www.odoo.com/documentation/18.0/administration/odoo_sh/getting_started/create.html) zum Projekt hinzufügen.

1. Odoo neu starten, den Entwicklermodus aktivieren und die Apps-Liste aktualisieren. Bei Bedarf den Standardfilter **Apps** entfernen, dann **IBANforge Bank Auto-fill** (`ibanforge_bank_autofill`) installieren.
2. **Einstellungen → IBANforge** öffnen, Ihren [API-Schlüssel](/de/docs/api-keys) einfügen und die Einstellungen speichern. Die voreingestellte API-Adresse beibehalten. Ohne Schlüssel sendet das Modul keine Netzwerkanfragen.
3. In einer Testdatenbank ein Partner-Bankkonto mit `DE89370400440532013000` anlegen. Das Bankfeld leer lassen, die IBAN eingeben und das Feld verlassen. Die erkannte Bank und den BIC oder die verknüpfte Bank prüfen, speichern und das Konto erneut öffnen, um die gespeicherte Bankverknüpfung zu kontrollieren.

Wenn die API nicht erreichbar ist oder kein BIC gefunden wird, bleibt die automatische Ergänzung aus; das Speichern wird dadurch nicht blockiert. Odoos Modul `base_iban` prüft weiterhin das IBAN-Format. Beim Speichern bleibt eine bereits eingetragene Bank erhalten. Eingabe und Speichern eines neuen Kontos können **zwei API-Aufrufe** benötigen: 200 monatliche Anfragen entsprechen daher nicht 200 manuell erfassten Konten. Die IBAN wird an die konfigurierte API übermittelt; das Ergebnis belegt keine Kontoinhaberschaft. [Verhalten und Grenzen des Moduls](https://github.com/cammac-creator/ibanforge-odoo/blob/18.0/ibanforge_bank_autofill/README.rst).

## KI-Agenten (MCP)

Claude Desktop, Claude Code, Cursor und jeder MCP-Client:

```bash
npx -y ibanforge-mcp        # stdio, 5 Tools, Free-Tier-Schlüssel optional
```

Oder der gehostete Transport, ohne Installation: `https://api.ibanforge.com/mcp` — 10 kostenlose Tool-Aufrufe pro IP und Tag, ganz ohne Schlüssel: der schnellste Weg für einen Assistenten, die Daten zu prüfen, bevor Sie sich festlegen.

## Was zurückkommt

Die Antwort, die die Rezepte ausgeben (Produktionsantwort, gekürzt):

```json
{
  "valid": true,
  "bic": { "code": "COBADEFFXXX", "bank_name": "Commerzbank", "city": "Köln" },
  "bank_code_check": {
    "value": "37040044",
    "status": "verified",
    "register": "Deutsche Bundesbank Bankleitzahlendatei",
    "authoritative": true,
    "as_of": "2026-08"
  }
}
```

`authoritative: true` heißt: das Nationalregister selbst hat geantwortet. Felder, die die Daten nicht tragen, sind `null` — nie geraten. Die [vollständige Semantik](/docs/iban-validate) erklärt, was `verified` verspricht und was nicht.

Siehe auch: [Was „verified" bedeutet](/docs/iban-validate) · [IBAN zu BIC](/docs/iban-to-bic) · [Test-IBAN-Generator](/tools/test-iban) · [Datenquellen](/docs/data-sources)
