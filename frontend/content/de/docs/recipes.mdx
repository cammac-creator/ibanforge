# Rezepte: erster IBAN-API-Aufruf in Ihrer Programmiersprache

## Mit einer Formatprüfung ohne Schlüssel beginnen

Dieser kostenlose Aufruf prüft Aufbau und Prüfziffer. Er sendet das Dokumentationsbeispiel an die API, ohne Bankabfrage und ohne Schlüsselerstellung:

```bash
curl --silent --show-error --fail-with-body --max-time 15 \
  --get --data-urlencode 'iban=DE89370400440532013000' \
  https://api.ibanforge.com/v1/iban/format
```

Für die folgenden Beispiele mit Bankinformationen [einmal einen Schlüssel erstellen](/de/docs/api-keys), aufbewahren und `IBANFORGE_API_KEY` in der Serverumgebung setzen. Das tatsächlich zurückgegebene Kontingent und den Nutzungsbericht lesen; Schutzmassnahmen können das anfängliche Kontingent reduzieren. Der Schlüssel gehört weder in Browsercode noch ins Repository oder eine Tabellenzelle. [Erster Test](/de/docs/onboarding) · [Aktuelle Preise](/de/pricing).

Jedes Beispiel sendet eine einzelne Validierungsanfrage und zeigt das Ergebnis, ohne eine Zahlung zu entscheiden. Die IBAN wird an die API übertragen; für den Test die Dokumentationsbeispiele verwenden. Eine Ausnahme beendet das Skript: Netzwerkfehler, Zeitüberschreitung und HTTP 402/429/5xx sind kein `valid: false`. Es gibt keine automatische Schlüsselerstellung, keinen Kauf und keine Wiederholung.

## Python

Das offizielle SDK mit `python -m pip install ibanforge` installieren und diesen Code als Python-Skript speichern:

```python
import json
import os
from ibanforge import IBANforge

key = os.environ.get("IBANFORGE_API_KEY", "").strip()
if not key:
    raise RuntimeError("Configurer IBANFORGE_API_KEY avant cet appel")

with IBANforge(api_key=key, timeout=15) as client:
    result = client.validate_iban("DE89370400440532013000")
    print(json.dumps(result, ensure_ascii=False, indent=2))
```

Für direkten HTTP-Zugriff `requests` mit `python -m pip install requests` installieren. Vor dem Ergebnis den HTTP-Status prüfen; diese Ausgabe erhält alle empfangenen JSON-Felder:

```python
import json
import os
import requests

key = os.environ.get("IBANFORGE_API_KEY", "").strip()
if not key:
    raise RuntimeError("Configurer IBANFORGE_API_KEY avant cet appel")

response = requests.post(
    "https://api.ibanforge.com/v1/iban/validate",
    json={"iban": "DE89370400440532013000"},
    headers={"Authorization": f"Bearer {key}"},
    timeout=15,
    allow_redirects=False,
)
response.raise_for_status()
if response.status_code != 200:
    raise RuntimeError(f"Réponse HTTP inattendue : {response.status_code}")
result = response.json()
if not isinstance(result, dict) or not isinstance(result.get("valid"), bool):
    raise RuntimeError("Réponse de validation incomplète")
print(json.dumps(result, ensure_ascii=False, indent=2))
```

HTTP-Fehler des SDK leiten sich von `IBANforgeError` ab; Netzwerkfehler und Zeitüberschreitungen bleiben `httpx`-Ausnahmen. Bei `requests` leiten sie sich von `requests.RequestException` ab. Die Skripte lassen Fehler weiterlaufen, ohne ein falsches Ergebnis auszugeben.

## Node.js / TypeScript

Mit Node.js 20 oder neuer als `premier-appel.mjs` speichern und `node premier-appel.mjs` ausführen. Das integrierte `fetch` benötigt kein Zusatzpaket. Das [offizielle TypeScript-SDK](https://github.com/cammac-creator/ibanforge/tree/main/sdks/typescript) bietet auch Typen und eigene Fehlerklassen.

```ts
const key = process.env.IBANFORGE_API_KEY?.trim();
if (!key) throw new Error("Configurer IBANFORGE_API_KEY avant cet appel");

const response = await fetch("https://api.ibanforge.com/v1/iban/validate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${key}`,
  },
  body: JSON.stringify({ iban: "DE89370400440532013000" }),
  signal: AbortSignal.timeout(15_000),
  redirect: "error",
});
if (!response.ok) throw new Error(`Échec HTTP : ${response.status}`);
const result = await response.json();
if (!result || typeof result.valid !== "boolean") {
  throw new Error("Réponse de validation incomplète");
}
console.log(JSON.stringify(result, null, 2));
```

## PHP

Mit PHP 8 oder neuer und aktivierter cURL-Erweiterung als `premier-appel.php` speichern und `php premier-appel.php` ausführen. Ein HTTP-Fehler oder unvollständiges JSON beendet das Skript vor einer Ergebnisausgabe:

```php
<?php
$key = trim(getenv("IBANFORGE_API_KEY") ?: "");
if ($key === "" || str_contains($key, "\r") || str_contains($key, "\n")) {
    throw new RuntimeException("Configurer IBANFORGE_API_KEY avant cet appel");
}
$request = curl_init("https://api.ibanforge.com/v1/iban/validate");
curl_setopt_array($request, [
    CURLOPT_POST => true,
    CURLOPT_HTTPHEADER => ["Content-Type: application/json", "Authorization: Bearer " . $key],
    CURLOPT_POSTFIELDS => json_encode(["iban" => "DE89370400440532013000"], JSON_THROW_ON_ERROR),
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_FOLLOWLOCATION => false,
    CURLOPT_CONNECTTIMEOUT => 5,
    CURLOPT_TIMEOUT => 15,
]);
$body = curl_exec($request);
$status = curl_getinfo($request, CURLINFO_HTTP_CODE);
curl_close($request);
if ($body === false) throw new RuntimeException("Réponse réseau indisponible");
if ($status !== 200) throw new RuntimeException("Échec HTTP : " . $status);
$result = json_decode($body, true, 512, JSON_THROW_ON_ERROR);
if (!is_array($result) || !is_bool($result["valid"] ?? null)) {
    throw new RuntimeException("Réponse de validation incomplète");
}
echo json_encode($result, JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR), PHP_EOL;
```

## Java

Mit Java 17 oder neuer das veröffentlichte SDK 1.8.1 zum Maven-Projekt hinzufügen. Jackson ist eine Abhängigkeit des SDK:

```xml
<dependency>
  <groupId>com.ibanforge</groupId>
  <artifactId>ibanforge-sdk</artifactId>
  <version>1.8.1</version>
</dependency>
```

Diese Klasse im Projekt als `PremierAppel.java` speichern:

```java
import com.ibanforge.sdk.IBANforge;
import com.ibanforge.sdk.model.IBANValidationResult;
import java.time.Duration;

public class PremierAppel {
    public static void main(String[] args) {
        String key = System.getenv("IBANFORGE_API_KEY");
        if (key == null || key.isBlank()) {
            throw new IllegalStateException("Configurer IBANFORGE_API_KEY avant cet appel");
        }
        IBANforge client = IBANforge.builder()
            .apiKey(key.trim()).timeout(Duration.ofSeconds(15)).build();
        IBANValidationResult result = client.validateIban("DE89370400440532013000");
        System.out.println(result.valid());
        System.out.println(result.bic() == null ? null : result.bic().code());
        System.out.println(result.bankCodeCheck());
    }
}
```

Ein fehlender BIC erscheint als `null`. `bankCodeCheck()` erhält die im Modell verfügbaren Felder, darunter Register und Datum. SDK-Fehler beenden das Beispiel. Die Modelle dieser Version enthalten nicht alle API-Ergänzungen, etwa bestimmte Hinweise und Metadaten; für das vollständige JSON einen HTTP-Client verwenden. [README und Methoden](https://github.com/cammac-creator/ibanforge/tree/main/sdks/java).

## C# / .NET

In einem .NET-8-Konsolenprojekt das [veröffentlichte Paket 1.8.1](https://www.nuget.org/packages/IBANforge.Sdk/1.8.1) installieren:

```bash
dotnet add package IBANforge.Sdk --version 1.8.1
```

Den Inhalt von `Program.cs` durch dieses Beispiel ersetzen:

```csharp
using IBANforge.Sdk;
using System.Text.Json;

var key = Environment.GetEnvironmentVariable("IBANFORGE_API_KEY");
if (string.IsNullOrWhiteSpace(key))
    throw new InvalidOperationException("Configurer IBANFORGE_API_KEY avant cet appel");

using var client = new IBANforgeClient(new IBANforgeOptions {
    ApiKey = key.Trim(),
    Timeout = TimeSpan.FromSeconds(15),
});
var result = await client.ValidateIbanAsync("DE89370400440532013000");
Console.WriteLine(JsonSerializer.Serialize(new {
    valid = result.Valid,
    bic = result.Bic,
    bank_code_check = result.BankCodeCheck,
}));
```

Fehlende Felder bleiben `null`; eine Ausnahme verhindert die Ergebnisausgabe. Diese Ausgabe ist eine Auswahl der Modellfelder und nicht das vollständige API-JSON. Eine bestehende Anwendung kann auch ihren eigenen `HttpClient` übergeben. [README und Modellgrenzen](https://github.com/cammac-creator/ibanforge/tree/main/sdks/dotnet).

## Google Sheets

Die offiziellen Funktionen speichern den Schlüssel in Ihren Nutzereigenschaften und senden Spalten in Batches. Kein Schlüssel gehört in eine Zelle.

1. [Laden Sie die drei Apps-Script-Dateien herunter](/integrations/ibanforge-sheets-6e5f9116f305.zip) und entpacken Sie das ZIP. Öffnen Sie in einer Testtabelle **Erweiterungen → Apps Script**.
2. Ersetzen Sie `Code.gs`, fügen Sie eine HTML-Datei namens `Sidebar` hinzu und übernehmen Sie `Sidebar.html`. Blenden Sie `appsscript.json` in den Projekteinstellungen ein und ersetzen Sie den Inhalt durch das mitgelieferte Manifest. Speichern.
3. Führen Sie `ibfShowSidebar` im Editor aus und autorisieren Sie das Script. Zurück in der Tabelle speichern Sie Ihren Schlüssel in der Seitenleiste, niemals in einer Zelle.
4. [Importieren Sie diese beiden Test-IBANs in Spalte A](/integrations/ibanforge-exemples-e69b509f4ab1.csv) über **Datei → Importieren**. Es sind ein öffentliches Dokumentationsbeispiel und seine Variante mit falscher Prüfziffer, keine Zahlungskonten. In B2 geben Sie `=IBAN_PRUEFUNG(A2:A3)` ein und lassen fünf Spalten frei.
5. Prüfen Sie beide Zeilen: `TRUE` für das erste Format, `FALSE` für das zweite. Danach Bank, BIC, Bankcode-Ergebnis und SEPA lesen. Fehlende Felder sind keine Zahlungsfreigabe.

Zwei IBANs verbrauchen zwei Kontingenteinheiten. Der Cache kann erneute Anfragen bis zu sechs Stunden vermeiden; seine Aufbewahrung ist nicht garantiert. **Manuelle Installation**; dieser Download ist kein Eintrag im Google Workspace Marketplace. [Alle Funktionen und Grenzen](/de/sheets).

## n8n

### Erster Test auf n8n Cloud oder eigenem Server

1. [Workflow-JSON herunterladen](/integrations/ibanforge-n8n-52a8fcab22ed.json) und **Import from File** im n8n-Workflow-Menü wählen. Es enthält nur zwei integrierte Nodes: Manual Trigger und HTTP Request. Keine Erweiterung und kein Schlüssel sind enthalten.
2. **Contrôler l’exemple de documentation** öffnen: POST an `/v1/iban/validate`, JSON mit dem öffentlichen Beispiel `DE89370400440532013000`. Einmal manuell ausführen.
3. In der Ausgabe `valid`, `bank_code_check` und verfügbare Quellen prüfen. Der Workflow führt weder Zahlungen noch Folgeaktionen aus. HTTP-Fehler, erschöpftes Kontingent und Zeitüberschreitungen stoppen den Schritt.
4. Für Ihr eigenes Schlüsselkontingent im HTTP-Node **Generic Credential Type → Header Auth** wählen: Name `Authorization`, Wert `Bearer ` gefolgt von Ihrem Schlüssel. Den Schlüssel in den Zugangsdaten speichern, niemals im exportierten JSON.

Der Test ohne Schlüssel verwendet das REST-Kontingent aus der [Startanleitung](/de/docs/onboarding), gemeinsam pro Netzwerkadresse. n8n-Cloud-Nutzer können eine Adresse teilen; bei erschöpftem Kontingent Ihren Schlüssel konfigurieren. [Workflow importieren](https://docs.n8n.io/workflows/export-import/) · [HTTP-Request-Optionen](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/).

### Lieferantendaten vor einem ERP-Import prüfen

[Prüfworkflow herunterladen](/integrations/ibanforge-n8n-revue-cf41a091e3a7.json), um die Originalzeilen zu erhalten und eine JSON-Datei mit Befunden zu erstellen. Er verwendet integrierte Nodes und einen API-Schlüssel, ohne Community-Erweiterung. Import und Ausführung wurden mit **n8n 2.46.6** geprüft; Node-Namen und Hinweise auf der Arbeitsfläche sind auf Französisch. Die Ausführung auf n8n Cloud wurde nicht getestet.

1. Die Datei in einen neuen Workflow importieren. In **Contrôler les IBAN avec la clé** Zugangsdaten vom Typ **Header Auth** wählen: `Authorization`, dann `Bearer ` gefolgt von Ihrem [API-Schlüssel](/de/docs/api-keys). Den Schlüssel niemals in das exportierte Workflow-JSON schreiben.
2. Die vier erfundenen Beispielzeilen ausführen. Sie zeigen fehlerhafte IBANs, eine Zeile ohne IBAN und ein Duplikat; sie gehören zu keinem echten Lieferanten.
3. In **Télécharger la revue JSON** die Ausgabe **Binary**, Feld `data`, öffnen und die Datei speichern. Der vorherige Node zeigt die Befunde je Zeile.
4. Für eigene Daten **Lignes fictives à remplacer** durch eine JSON-Quelle mit **1 bis 100 Zeilen** ersetzen, mit `iban` als Text. `bic` und `bank_name` sind optional; weitere Spalten bleiben in `original` erhalten.

Vorschläge bleiben in `review.proposal`, getrennt von den Originalwerten. `ask_supplier` meldet eine konkrete Auffälligkeit; `review` bewahrt Unsicherheiten, fehlende Felder oder Duplikate; `enrichment_proposal` enthält nur vorgeschlagene Felder mit ihren Quellen. Eine nicht identifizierte Bank wird niemals als bestätigt behandelt. Kein Status gibt eine Zahlung frei.

Nur IBANs werden an die API gesendet. Der Stapel verbraucht [eine Kontingenteinheit je IBAN](/de/docs/iban-batch), auch bei Duplikaten. HTTP-Fehler, ein erschöpftes Kontingent oder widersprüchliche Antworten stoppen den Workflow ohne neue Datei, automatische Wiederholung oder Kauf. Zeilen ohne IBAN bleiben ohne API-Aufruf zur Prüfung erhalten. Originaldaten und Berichte verbleiben in n8n und dessen Ausführungshistorie: Die Aufbewahrung vor der Nutzung echter Daten passend einstellen.

### Community-Erweiterung für selbst gehostetes n8n

Das veröffentlichte Paket [`n8n-nodes-ibanforge@0.1.3`](https://www.npmjs.com/package/n8n-nodes-ibanforge) bietet IBAN-Validierung, BIC-Suche, Schweizer Clearing und Compliance-Vorprüfungen auf Bankebene. Dieses Rezept gilt für **selbst gehostetes n8n**, mit einem Owner- oder Admin-Konto. Die Installation eines Pakets aus npm ist auf n8n Cloud nicht verfügbar; dort ist ein verifizierter Eintrag erforderlich. Siehe die [Installationsanleitung von n8n](https://docs.n8n.io/integrations/community-nodes/installation-and-management/).

1. **Settings → Community nodes → Install** öffnen und `n8n-nodes-ibanforge@0.1.3` eingeben.
2. Einen [kostenlosen API-Schlüssel](/de/docs/api-keys) beziehen (25 Anfragen/Monat ohne E-Mail, 200 nach Beanspruchung, ohne Karte). In einem neuen Workflow **Manual Trigger** mit **IBANforge** verbinden und den Schlüssel in den Zugangsdaten **IBANforge API** hinterlegen.
3. **Validate IBAN** auswählen, das Dokumentationsbeispiel `DE89370400440532013000` eingeben und den Schritt ausführen.
4. Die JSON-Ausgabe prüfen: `valid` sollte für dieses Beispiel `true` sein, `bank_code_check` beschreibt das Registerergebnis und `bic` die Bank, sofern sie ermittelt werden kann. Eine abgeschlossene Operation mit diesen Feldern belegt den ersten API-Aufruf; ein grüner Verbindungstest allein genügt nicht.

In Version 0.1.3 ruft der Verbindungstest den öffentlichen Endpunkt `/v1/demo` auf, der den Schlüssel nicht prüft. Vor dem Einsatz des Workflows das tatsächliche Ergebnis von **Validate IBAN** kontrollieren. Weder ein gültiges Format noch eine identifizierte Bank belegen, dass das Konto existiert oder einem bestimmten Zahlungsempfänger gehört.

Für eine manuelle Installation die folgenden Befehle **als Benutzer des n8n-Dienstes** ausführen, gegebenenfalls in dessen Container. Anschliessend n8n neu starten:

```bash
mkdir -p ~/.n8n/nodes
cd ~/.n8n/nodes
npm install n8n-nodes-ibanforge@0.1.3
```

Der Node verarbeitet jedes eingehende Element einzeln; er hat keine Batch-Operation. Eine Liste mit 100 Elementen kann daher 100 Anfragen verbrauchen. [Details zur manuellen Installation](https://docs.n8n.io/integrations/community-nodes/installation-and-management/manual-installation/).

## Odoo

Das [öffentliche Odoo-Modul](https://github.com/cammac-creator/ibanforge-odoo/tree/18.0), Version **18.0.1.0.0** (AGPL-3), füllt BIC und Bankname aus, wenn die API sie ermitteln kann. Es benötigt **Odoo 18 mit Unterstützung für eigene Python-Module**, auf Ihrem eigenen Server oder auf Odoo.sh. [Odoo Online unterstützt diese Module nicht](https://www.odoo.com/documentation/18.0/administration/odoo_online.html). Diese Installation verwendet das Quellcode-Repository und ist nicht von einem Eintrag im Odoo Apps Store abhängig.

Auf Ihrem eigenen Odoo-Server das Repository in ein Verzeichnis Ihrer Wahl klonen:

```bash
git clone --branch 18.0 --single-branch https://github.com/cammac-creator/ibanforge-odoo.git /path/to/ibanforge-odoo
```

`/path/to/ibanforge-odoo` zur bestehenden `addons_path`-Liste von Odoo hinzufügen und die anderen Einträge beibehalten. Das Modul liegt im **Unterverzeichnis**: Das Manifest muss unter <code className="break-all">/path/to/ibanforge-odoo/ibanforge_bank_autofill/__manifest__.py</code> liegen. Alternativ nur dieses Verzeichnis `ibanforge_bank_autofill` in ein bereits konfiguriertes Addons-Verzeichnis kopieren. Die Python-Bibliothek `requests` muss in der Odoo-Umgebung verfügbar sein. Auf Odoo.sh dieses Modulverzeichnis nach der [Anleitung für eigene Module](https://www.odoo.com/documentation/18.0/administration/odoo_sh/getting_started/create.html) zum Projekt hinzufügen.

1. Odoo neu starten, den Entwicklermodus aktivieren und die Apps-Liste aktualisieren. Bei Bedarf den Standardfilter **Apps** entfernen, dann **IBANforge Bank Auto-fill** (`ibanforge_bank_autofill`) installieren.
2. **Einstellungen → IBANforge** öffnen, Ihren [API-Schlüssel](/de/docs/api-keys) einfügen und die Einstellungen speichern. Die voreingestellte API-Adresse beibehalten. Ohne Schlüssel sendet das Modul keine Netzwerkanfragen.
3. In einer Testdatenbank ein Partner-Bankkonto mit `DE89370400440532013000` anlegen. Das Bankfeld leer lassen, die IBAN eingeben und das Feld verlassen. Die erkannte Bank und den BIC oder die verknüpfte Bank prüfen, speichern und das Konto erneut öffnen, um die gespeicherte Bankverknüpfung zu kontrollieren.

Wenn die API nicht erreichbar ist oder kein BIC gefunden wird, bleibt die automatische Ergänzung aus; das Speichern wird dadurch nicht blockiert. Odoos Modul `base_iban` prüft weiterhin das IBAN-Format. Beim Speichern bleibt eine bereits eingetragene Bank erhalten. Eingabe und Speichern eines neuen Kontos können **zwei API-Aufrufe** benötigen: 200 monatliche Anfragen entsprechen daher nicht 200 manuell erfassten Konten. Die IBAN wird an die konfigurierte API übermittelt; das Ergebnis belegt keine Kontoinhaberschaft. [Verhalten und Grenzen des Moduls](https://github.com/cammac-creator/ibanforge-odoo/blob/18.0/ibanforge_bank_autofill/README.rst).

## KI-Agenten (MCP)

Remote MCP: `https://api.ibanforge.com/mcp` in einem kompatiblen Client hinzufügen. Für einen lokalen Prozess:

```bash
npx -y ibanforge-mcp
```

Oder der gehostete Transport, ohne Installation: `https://api.ibanforge.com/mcp` — 25 kostenlose Tool-Aufrufe pro Woche und Quelladresse, ganz ohne Schlüssel (ISO-Woche in UTC, Neustart montags um 00:00 UTC): der schnellste Weg für einen Assistenten, die Daten zu prüfen, bevor Sie sich festlegen. Mit Ihrem Schlüssel im Header `Authorization: Bearer` zählen seine Aufrufe genau wie bei der REST-API auf diesen Schlüssel ([wohin damit](/docs/mcp)).

## Das Ergebnis vor der Integration lesen

Bank, BIC, Quellen und Daten hängen von der erhaltenen Antwort ab. Kein fester Bankname ist Voraussetzung für den Erfolg dieser Rezepte.

| Feld | Einordnung |
|---|---|
| `valid` | Prüfung der IBAN, getrennt vom Bankcode-Ergebnis. Ein HTTP-Fehler ist kein ungültiges Ergebnis. |
| `bic` | Bankidentifikation, falls verfügbar; `null` bleibt unbekannt. |
| `bank_code_check` | Status, Grund, Quelle und Datum der verwendeten Referenz. Ein Teilregister kann das Fehlen einer Bank nicht beweisen. |
| `bank_code_holder`, Metadaten und Rückzugsfelder | Zusätzliche Felder der HTTP-Antwort; prüfen, ob die verwendete SDK-Modellversion sie enthält. |

Diese Prüfungen belegen weder die Existenz noch den Inhaber eines Kontos. Gelieferte Bankdaten nicht automatisch ersetzen. Antwort und Herkunft im eigenen Prüfablauf erhalten und die Aufbewahrung an die Daten anpassen.
