# VoP-Register und Empfängerüberprüfung

IBANforge zeigt, was die verfügbaren Quellen über die **ermittelte Bank** aussagen. Es fordert diese Bank nicht auf, den Empfängernamen mit der IBAN abzugleichen. Es bestätigt weder die Existenz des Kontos noch seinen Inhaber oder den Erfolg einer Überweisung.

Im [Verification-of-Payee-Scheme des EPC](https://www.europeanpaymentscouncil.eu/what-we-do/other-schemes/verification-payee-vop) erfolgt der Namensabgleich zwischen Zahlungsdienstleistern. Das Ergebnis Ihres PSP bleibt von den IBANforge-Indikatoren getrennt.

## Diese Felder lesen

Wenn die Antwort auf `POST /v1/iban/validate` einen `sepa`-Block enthält:

| Feld | Aussage |
|---|---|
| `vop_required` | Der von der API berechnete Länderindikator. Er belegt weder die Teilnahme der Bank noch für sich allein deren Pflichten. |
| `vop_participant` | `true`, wenn die ermittelte Bank im gelesenen Register aktiv ist; `false`, wenn sie dort nicht aktiv ist; `null`, wenn das Ergebnis nicht feststeht. |
| `vop_register_status` | Die Einzelheit: `active`, `pending`, `inactive`, `not_listed` oder `null`. Ausserhalb des SEPA-Raums kann dieses Feld fehlen. |
| `register_source`, `register_as_of` | EPC-Quelle und Extraktionsdatum, wenn ein EPC-Register für diese Bank gelesen wurde. |

`bank_code_check.as_of` datiert das **Bankcode-Register**, nicht das VoP-Register. Auch `sepa.register_source` beweist allein keine VoP-Abfrage: Die Angabe kann aus einem anderen EPC-Register für Zahlungsschemes stammen.

`risk_indicators.vop_coverage` übernimmt den Länderindikator. Für den Status der Bank sind `sepa.vop_register_status` und `sepa.vop_participant` massgeblich.

## Den Status ohne erfundenes Namensergebnis interpretieren

| Registerstatus | Bedeutung für die Prüfung |
|---|---|
| `active` | Die gelesene Quelle führt eine aktive Registrierung. Das ist weder eine Verfügbarkeitsprüfung in Echtzeit noch ein «Match». |
| `pending` | Registrierung ausstehend. Nicht als aktive Teilnahme behandeln. |
| `inactive` | Inaktive Registrierung in der gelesenen Quelle. Keine Aussage zum Kontoinhaber. |
| `not_listed` | Kein Status für den ermittelten BIC im gelesenen Register gefunden. Das beweist keine Namensabweichung. |
| `null` oder fehlendes Feld | Information nicht festgestellt oder Feld nicht anwendbar. Das bedeutet nicht «No Match». |

Ein nicht ermittelter BIC, ein fehlendes Register oder ein Lesefehler kann `null` ergeben. Ausserhalb des SEPA-Raums kann der Länderumfang `vop_participant: false` ergeben, ohne das VoP-Register zu lesen. Ein boolescher Wert allein beweist daher keine Registerabfrage.

## Erster Aufruf

Verwenden Sie einen Beispielwert, um die Felder zu lesen; senden Sie keinen Kontoinhabernamen an diese Route.

```bash
curl --silent --show-error --fail-with-body \
  https://api.ibanforge.com/v1/iban/validate \
  -H 'Content-Type: application/json' \
  -d '{"iban":"CH1000230000000012345"}'
```

Dieser Aufruf kann den Validierungstest ohne Schlüssel innerhalb seines verfügbaren Kontingents nutzen. Die [Einstiegsanleitung](/de/docs/onboarding) erklärt den Zugang und das Aufbewahren eines Schlüssels für eine Integration. Registerwerte ändern sich: Das Beispiel verspricht keinen VoP-Status für die zurückgegebene Bank. HTTP 200 bestätigt weder Gültigkeit noch Kontoinhaberschaft.

## In einem ERP- oder Zahlungsablauf

1. `valid` und das Ergebnis von `bank_code_check` lesen. Formatfehler, nicht zugeteilten Bankcode und unbestimmte Information unterscheiden.
2. VoP-Status und verfügbare Quellenangaben zur Prüfung aufbewahren. Eine aktive Bank kann zum Zeitpunkt der tatsächlichen Anfrage dennoch nicht erreichbar sein.
3. Falls Ihr Prozess einen Namensabgleich benötigt, den Dienst Ihres PSP nutzen und **dessen** Ergebnis behalten: Übereinstimmung, nahe Übereinstimmung, keine Übereinstimmung oder Prüfung nicht möglich.
4. `false`, `null` und `not_listed` nicht in ein Namensergebnis umwandeln. Aufgrund dieser Indikatoren allein weder eine IBAN ersetzen noch eine Zahlung auslösen.

Der [EPC](https://www.europeanpaymentscouncil.eu/what-we-do/other-schemes/verification-payee-vop) veröffentlicht Regeln, Geltungsdaten und Bedingungen des Schemes. Das IBAN-Land allein beschreibt nicht den tatsächlich angebotenen Dienst Ihrer Bank.
