# Finnische Bankcodes: die Codes der monetären Institute

Finnische Bankcodes stammen aus der Liste der **Codes der monetären Institute von Finance Finland**, und sie verhalten sich in drei Punkten anders als die nationalen Register, die wir in Deutschland, Österreich oder Belgien lesen.

Erstens ist der Code kein fester Ausschnitt der IBAN: Finnische Institutscodes sind **ein bis vier Zeichen** am Anfang des BBAN, die Prüfung liest deshalb das *längste vergebene Präfix* statt eines Schnitts nach Position. Ein fester dreistelliger Ausschnitt fragt nach einem Code, den niemand erhalten hat, und verneint eine Gruppe mit kürzerem Code.

Zweitens **sind finnische Codes Bankengruppen zugeteilt, nicht einzelnen Instituten.**

Drittens, und darauf ist zu entwerfen, **ist die Liste, die wir führen, unvollständig.** Sie ist eine Abschrift der Veröffentlichung von Finance Finland vom 16. März 2026, die nichts automatisch aktualisiert. Seit dem 16. September 2026 behandelt die API sie deshalb als Liste, die Inhaber nennt, ohne jemanden abzulehnen: Ein Treffer wird ausgeliefert, ein Fehlen ist keine Ablehnung.

Der Herausgeber hat die Bedingungen für die Weiterverwendung der Liste nie bestätigt: Seit dem 25. September 2026 liest die API sie aus einer privaten Datei, nicht mehr aus ihrem öffentlichen Repository. Eine Antwort ohne diese Datei sagt, dass die Liste nicht abgefragt wurde (`status: "unavailable"`), nie, dass ein Code abgelehnt ist.

## Ein Aufruf

```bash
curl -X POST https://api.ibanforge.com/v1/iban/validate \
  -H "Content-Type: application/json" \
  -d '{"iban": "FI2112345600000785"}'
```

Die Antwort ist unten auf den Block gekürzt, um den es auf dieser Seite geht. Die Werte der Liste selbst (der Code, die Gruppe und der Monat der Liste) sind hier ausgelassen; die API liefert sie.

```json
{
  "valid": true,
  "bank_code_check": {
    "value": "…",
    "status": "verified",
    "match": "register",
    "register": "Finance Finland monetary institution codes (allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial)",
    "authoritative": false,
    "as_of": "…",
    "institution": { "name": "…", "street": null, "post_code": null, "town": null, "country": "FI" }
  }
}
```

Das ist **Finnlands offizielle Beispiel-IBAN**. `value` ist der vergebene Code, um den es in der Antwort geht, und kann kürzer als drei Ziffern sein; `institution.name` ist die Bankengruppe, die ihn hält.

## Lesen Sie die `register`-Zeichenkette, sie arbeitet

Sehen Sie, was `register` sagt: *„allocated to banking groups, not individual institutions; transcribed list, a miss is not a denial"*. Beide Zusätze fahren **in der Antwort mit**, denn eine finnische Antwort behauptet weniger als eine deutsche oder österreichische, in beide Richtungen:

| Register | Was ein `verified`-Ergebnis heißt | Was ein Code heißt, der auf der Liste fehlt |
|---|---|---|
| DE, AT, BE, SK, CZ, BG, CH / LI | der Code ist **diesem benannten Institut** zugeteilt | nicht vergeben: `not_in_register`, `authoritative: true` |
| **FI** | der Code ist **dieser Bankengruppe** zugeteilt | nichts: Die Antwort fällt auf unsere zusammengesetzte Zuordnung zurück, `authoritative: false` |

## Was ein Fehlen hier bedeutet

Ein finnischer Code, den die Liste nicht führt, wird **nie abgelehnt**. Die Antwort fällt auf das zurück, was jedes Land ohne Register erhält: unsere zusammengesetzte Bankcode-Zuordnung, `authoritative: false`, und schlimmstenfalls `status: "not_in_register"` mit `reason: "absent_from_reference_data"`, was etwas über unsere Daten sagt und nichts über den Code. `not_allocated` sehen Sie für Finnland nie. Daneben sagt die Prüfziffer der IBAN in jedem Fall weiterhin `valid: true`.

Der Grund liegt in der Liste selbst: Eine Abschrift, die nichts aktualisiert, kann ein neues oder umbenanntes Institut nicht von einem Code unterscheiden, den niemand hält, und eine Ablehnung aus einer elf Monate alten Liste ist kein Grund, eine Zahlung zu stoppen. Finnland kehrt zu den Registern zurück, die ein Fehlen entscheiden, sobald die Liste gegen eine aktuelle Veröffentlichung neu gelesen ist.

## Der `institution`-Block für Finnland

Ein Treffer trägt einen `institution`-Block mit dem Namen der **Bankengruppe**, der der Code gehört, ohne Adresse: Die Liste veröffentlicht keine, und ein Gruppencode hat keinen einzelnen Sitz zu beschreiben. `authoritative: false` bleibt daneben, aus dem oben genannten Grund.

## Frische

`as_of` ist der Monat der Liste selbst, nicht unsere monatliche Aktualisierung: Nichts liest die Veröffentlichung von Finance Finland automatisch neu ein, und eine Antwort, auf die Sie handeln, muss sagen, wie alt ihre Liste ist.

## Die ehrlichen Grenzen

- **Ein Treffer bestätigt die Gruppe, nicht die Filiale und nicht das Institut.** Wenn Ihr Prozess genau wissen muss, welche Mitgliedsbank das Konto führt, ist eine finnische Bankcode-Prüfung nicht das Werkzeug.
- **Ein Fehlen beweist nichts.** Die Liste ist unvollständig und datiert; ein fehlender Code ist keine Ablehnung.
- **Wir prüfen den Bankcode, nie das Konto und nie den Inhaber.** Nichts in dieser Antwort blickt über den Code am Anfang des BBAN hinaus.
- **Die Präfixlänge zählt.** Die Prüfung nimmt das längste vergebene Präfix; ein naiver Ausschnitt fester Breite aus einem finnischen BBAN erzeugt falsche Abfragen gegen jedes Register, auch gegen dieses.
- **Keine Adressen.** Die Liste nennt Gruppen und veröffentlicht keinen Sitz.
