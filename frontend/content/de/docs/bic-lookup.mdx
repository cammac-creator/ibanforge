# BIC/SWIFT-Suche

`GET /v1/bic/:code` sucht einen **bereits bekannten BIC** im Verzeichnis und liefert verfügbare Referenzdaten zum Institut. Wenn Sie von einer IBAN ausgehen, nutzen Sie [IBAN zu BIC](/de/docs/iban-to-bic). Die Suche bestätigt weder ein Konto noch dessen Inhaber oder die Durchführbarkeit einer Zahlung.

Dokumentation geprüft am 4. November 2026. Der [OpenAPI-Vertrag](https://api.ibanforge.com/openapi.json) beschreibt die vollständige Antwort.

## Erster Aufruf mit Ihrem Schlüssel

Bewahren Sie den über den [Einstieg](/de/docs/onboarding) erhaltenen Schlüssel auf und setzen Sie `IBANFORGE_API_KEY` auf Ihrem Server. API-Schlüssel und x402 sind getrennte Zugangswege. Der REST-Test ohne Schlüssel gilt nur für die Prüfung einer einzelnen IBAN, nicht für diese Suche. Die [Preise und Kontingente](/de/pricing) erläutern den jeweiligen Zugang.

```bash
curl --silent --show-error --fail-with-body --max-time 20 \
  'https://api.ibanforge.com/v1/bic/UBSWCHZH' \
  -H "X-API-Key: ${IBANFORGE_API_KEY:?clé requise}"
```

`code` akzeptiert einen BIC mit 8 oder 11 Zeichen, unabhängig von Gross- und Kleinschreibung. Ein BIC8 wird als BIC11 mit der Endung `XXX` gesucht. Das garantiert keinen vorhandenen Eintrag für den Hauptsitz. Ersetzen Sie den Platzhalter `:code`, statt ihn wörtlich zu senden.

## Das Ergebnis vor der Verwendung lesen

Eine formal gültige Suche liefert **HTTP 200 auch bei `found: false`**. Ein fehlender Verzeichniseintrag ist kein `404 bic_not_found` und beweist nicht, dass der Code unzugeteilt ist.

| Feld | Bedeutung |
|---|---|
| `bic`, `bic8`, `bic11` | Normalisierter Code und seine beiden Formen. |
| `valid_format` | Prüfung der BIC-Struktur, getrennt vom Eintrag im Verzeichnis. |
| `found`, `institution` | Ein Eintrag nennt das Institut; andernfalls `found: false` und `institution: null`. |
| `country.code`, `country.name` | Das Land ist ein Objekt; `countryCode` gehört nicht zu dieser Antwort. |
| `city`, `branch_code`, `branch_info` | Verfügbare Orts- und Filialangaben; fehlende Angaben können null sein. |
| `lei`, `lei_status` | Verfügbare Kennung und Status der juristischen Person, keine Bestätigung des Kontoinhabers. |
| `source`, `source_name` | Verwendeter Datenbestand und sein lesbarer Name. |
| `source_as_of` | Inhaltsdatum einer eingefrorenen Kopie, falls vorhanden. Ein fehlendes Feld bedeutet nicht, dass die Daten aktuell sind. |
| `listed_in_current_source` | Spur des BIC8 in einer in diesem Zyklus aktualisierten Quelle. `null` bleibt unbekannt und wird nicht zu `false`. |
| `shared_bic8`, `note` | Zusätzliche Angaben, wenn kein eindeutiges Institut aufgelöst wurde. |

Bei einem gemeinsamen BIC8 ohne `XXX`-Eintrag kann `shared_bic8` die vorhandenen Einträge unter diesem Präfix beschreiben. Fragen Sie nach dem vollständigen BIC11 der Gegenpartei; wählen Sie keine beliebige Bank aus.

`address` kann null sein. Falls eine Adresse vorliegt, erhalten Sie Quelle und Datum; eine Bankadresse ersetzt nicht die Adresse des Begünstigten. Zusätzliche Blöcke wie `postal_address`, `official_identity` oder `pra_authorisation` behalten ihre Quellenhinweise. Siehe [Datenquellen und Grenzen](/de/docs/data-sources).

Der Block `sanctions` betrifft das durch den BIC8 bezeichnete Institut. Er kann auch bei `found: false` vorliegen. Lesen Sie `screened`, `listed` und gegebenenfalls `unscreened_lists`: Eine nicht konsultierte Liste ergibt keinen negativen Befund. Der Name des Begünstigten wird damit nicht geprüft.

## Beispiele für den Server

Die Beispiele wählen einige Felder zum Prüfen der Antwort aus. Erhalten Sie die vollständige Antwort in Ihrer eigenen Verarbeitung gemäss Ihren Aufbewahrungsregeln. Kein Beispiel gibt eine Zahlung frei.

### Python, Standardbibliothek

```python
import http.client
import json
import os

key = os.environ["IBANFORGE_API_KEY"]
if not key.strip():
    raise ValueError("Clé API vide")

connection = http.client.HTTPSConnection("api.ibanforge.com", timeout=20)
try:
    connection.request("GET", "/v1/bic/UBSWCHZH", headers={"X-API-Key": key})
    response = connection.getresponse()
    if response.status != 200:
        raise RuntimeError(f"HTTP {response.status} : consulter les erreurs API")
    data = json.loads(response.read())
finally:
    connection.close()

print(json.dumps({
    "found": data["found"],
    "institution": data.get("institution"),
    "source_name": data.get("source_name"),
    "source_as_of": data.get("source_as_of"),
    "listed_in_current_source": data.get("listed_in_current_source"),
    "shared_bic8": data.get("shared_bic8"),
    "note": data.get("note"),
}, ensure_ascii=False))
```

### Node.js 22, Datei `.mjs`

```javascript
const key = process.env.IBANFORGE_API_KEY;
if (!key?.trim()) throw new Error("Clé API absente ou vide");

const response = await fetch("https://api.ibanforge.com/v1/bic/UBSWCHZH", {
  headers: { "X-API-Key": key },
  signal: AbortSignal.timeout(20_000),
  redirect: "error",
});
if (response.status !== 200) {
  throw new Error(`HTTP ${response.status} : consulter les erreurs API`);
}
const data = await response.json();
console.log(JSON.stringify({
  found: data.found,
  institution: data.institution ?? null,
  source_name: data.source_name ?? null,
  source_as_of: data.source_as_of ?? null,
  listed_in_current_source: data.listed_in_current_source ?? null,
  shared_bic8: data.shared_bic8 ?? null,
  note: data.note ?? null,
}));
```

## Fehler und nächste Schritte

| HTTP | Behandlung |
|---|---|
| `400` | `error` und `message` lesen: etwa ungültige Struktur oder wörtlicher Platzhalter. Keinen korrigierten BIC erfinden. |
| `402` | Zugangsgrund lesen: ungültiger Schlüssel, verbrauchtes Kontingent oder erforderliche Zahlung. Denselben Schlüssel behalten; nicht automatisch bezahlen. |
| `403` | Eine angeforderte Verifikation gemäss Antwort durchführen. |
| `429` | Ein geliefertes `Retry-After` beachten und Wiederholungen begrenzen. |
| `5xx` oder Zeitüberschreitung | Kein verwertbares Ergebnis dieses Versuchs; begrenzte Wiederholung und Prüfung vorsehen. |

Die Beispiele lehnen auch Weiterleitungen ab. Der Schlüssel gehört weder in URLs und Bildschirmfotos noch in ausgelieferten Browsercode. Enthält die Antwort `attribution`, sind Text und Link bei der Anzeige für Nutzer zu beachten.
