# Bankprüfungen und Compliance-Indikatoren

Diese Route ergänzt Indikatoren auf **Bankebene**: Abgleich mit den angekündigten Listen (OFAC, EU, UN), Länder-/FATF-Daten, SEPA-Erreichbarkeit und VoP-Registrierung. Sie prüft weder Kontoinhaberschaft noch Kontoexistenz oder Empfängername und führt keine Zahlung aus. Sie ist kein reguliertes AML/CFT-Produkt.

```text
POST https://api.ibanforge.com/v1/iban/compliance
```

## Mit Schlüssel aufrufen

Ein API-Schlüssel oder eine x402-Zahlung ist erforderlich; der schlüssellose Test der Einzelvalidierung gilt nicht für diese Route. Mit Schlüssel verbraucht ein Aufruf eine Kontingenteinheit oder ein vorausbezahltes Guthaben und `cost_usdc` ist `0`. Mit x402 kostet ein Aufruf **0,02 USDC**. Siehe [API-Schlüssel](/de/docs/api-keys), [Preise](/de/pricing) und [x402](/de/docs/x402).

Die serverseitige Umgebungsvariable `IBANFORGE_API_KEY` enthält Ihren vorhandenen Schlüssel. Die Werte sind Dokumentationsbeispiele. Senden Sie **entweder `iban` oder `bic`**, niemals beide Werte ausgefüllt.

```bash
curl --fail-with-body --silent --show-error \
  https://api.ibanforge.com/v1/iban/compliance \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${IBANFORGE_API_KEY:?}" \
  -d '{"iban":"DE89370400440532013000"}'
```

```bash
curl --fail-with-body --silent --show-error \
  https://api.ibanforge.com/v1/iban/compliance \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${IBANFORGE_API_KEY:?}" \
  -d '{"bic":"COBADEFFXXX"}'
```

Der Pfad mit `bic` akzeptiert einen BIC mit 8 oder 11 Zeichen und prüft keine IBAN. Seine Antwort enthält `bic` (Zeichenkette), `bic8`, `valid_format`, `found`, `institution`, `country`, `compliance`, `meta`, `cost_usdc` und `processing_ms` sowie gegebenenfalls `note`. `found: false` bedeutet, dass das Verzeichnis das Institut nicht benannt hat; der BIC-Abgleich kann dennoch erfolgen. Diese Antwort unterscheidet sich vom IBAN-Pfad, wo `bic`, falls vorhanden, ein Objekt ist.

## Feststellungen vor dem Score lesen

Der IBAN-Pfad erhält die [Felder der Einzelvalidierung](/de/docs/iban-validate) und ergänzt `compliance` und `meta`. Ein `200` kann eine ungültige IBAN enthalten. Das gegebenenfalls vorhandene Objekt `checks` trennt ebenfalls die Prüfachsen. Fehlende Daten werden nicht zu negativen Feststellungen.

| Feld in `compliance` | Bedeutung |
|---|---|
| `sanctions.bank_screened` | Eine Bank wurde mit geladenen Listen verglichen; `true` garantiert nicht die Verfügbarkeit aller angekündigten Listen. |
| `sanctions.institution_listed` | `true`: Treffer gefunden; `false`: kein Treffer im vollständig abgefragten Umfang; `null`: keine negative Feststellung möglich, weil keine Bank geprüft wurde oder eine Liste fehlte. |
| `sanctions.bank_sanctioned`, `matched_lists` | Bisherige Ergebnisfelder. `false` oder eine leere Liste nur zusammen mit Abdeckung und Flags lesen. |
| `sanctions.payee_screened` | Immer `false`: kein Abgleich des Kontoinhabernamens. |
| `sanctions.country_sanctioned` | Ländersignal aus der Datenbank, getrennt von einer Banklistung und einer rechtlichen Bewertung der Transaktion. |
| `sanctions.fatf_status` | `member`, `suspended`, `grey_list`, `black_list` oder `non_member`. Nichtmitgliedschaft ist keine Risikolistung. |
| `reachability.screened` | Antwort durch ein Bankregister oder ein Land außerhalb des SEPA-Geltungsbereichs festgestellt. |
| `reachability.sct`, `sdd`, `sepa_instant` | Indikatoren der Verfahren; ohne Prüfung sind `false`-Werte Vorgaben. |
| `reachability.listed_in_epc_registers` | Mindestens ein verfügbares Verfahren; `null`, wenn nicht festgestellt. Auch `screened` und Herkunft lesen. |
| `vop.screened`, `register_status` | Registerstatus: `active`, `pending`, `inactive`, `not_listed` oder `null`, wenn nicht festgestellt. |
| `vop.participant`, `status` | Bisherige Felder: `participant` ist bei `active` wahr; `status` verwendet weiterhin `not_found`. Kein Name/IBAN-Abgleich. |
| `reachability.source`, `as_of`; `vop.source`, `as_of` | EPC-Quellenhinweis und Extraktionsdatum bei Registerabfrage für die Bank; fehlen bei einer Antwort anhand des Landes. Datum `null`, wenn unbekannt. |
| `risk_score` | Redaktioneller Score von 0–100 und Kategorie; `null` / `unassessable` bei ungültiger IBAN. Weder Betrugswahrscheinlichkeit noch Freigabe. |
| `risk_level` | `low` (0–19), `medium` (20–39), `elevated` (40–59), `high` (60–79), `critical` (80–100), `unassessable`. |
| `flags` | Maschinenlesbare Feststellungen und Grenzen einschließlich fehlender Quellen. Nicht jedes Flag erhöht den Score. |

## Fälle unterscheiden

Eine ungültige IBAN liefert `risk_score: null`, `risk_level: "unassessable"` und das Flag `iban_invalid`. Ist die IBAN gültig, aber eine Quelle nicht lesbar, können andere Achsen weiterhin antworten. Abdeckung, `null` und `*_unavailable`-Flags müssen berücksichtigt werden. Ein numerischer Score kann daher mit einer unvollständigen Prüfung einhergehen.

Die Kategorien sind `low` (0–19), `medium` (20–39), `elevated` (40–59), `high` (60–79) und `critical` (80–100). `low` ist keine Zahlungsfreigabe. Insbesondere erhöhen fehlende SEPA- oder VoP-Register den Score nicht: Lesen Sie diese Flags getrennt. Die Antwort dokumentiert eine Prüfung und ersetzt keine Konto- oder Empfängerprüfung.

## Umfang und Herkunft

Der Bankabgleich verwendet normalerweise den exakten BIC8. Bei einer russischen Bank werden die Standard-SWIFT-BICs der Einträge derselben Lizenz anhand ihrer ersten sechs Zeichen verglichen. Sekundäre BICs werden nicht verglichen. Ohne nutzbaren BIC bleibt die Bankachse ungeprüft; eine Listung ohne BIC oder unter einem anderen Präfix kann unentdeckt bleiben.

| Feld in `meta` | Bedeutung |
|---|---|
| `scope`, `disclaimer` | `bank_bic_only` und der Einschränkungstext; mit dem Bericht erhalten. |
| `sources` | Geladene Quellen als kommagetrennte Zeichenkette oder `null`; kein Beleg, dass jede Achse für diesen Aufruf abgefragt wurde. |
| `sanctions_as_of` | Aktualisierungsdatum der Compliance-Daten oder `null`; keine Garantie gleicher Aktualität aller Listen. |
| `fatf_as_of` | Monat der abgebildeten Plenarsitzung oder `null`. |
| `country_risk_as_of`, `country_risk_scope` | Datum und Erklärung der redaktionellen Länderachse, getrennt vom FATF-Status. |

Ein Aktualisierungsplan ersetzt diese gelieferten Daten nicht. Erhalten Sie auch Quellenhinweise und den gegebenenfalls vorhandenen `attribution`-Block des IBAN-Pfads. Die VoP-Registrierung einer Bank löst keine Empfängerprüfanfrage aus: siehe [unseren VoP-Leitfaden](/de/docs/vop) und die [EPC-Beschreibung](https://www.europeanpaymentscouncil.eu/what-we-do/other-schemes/verification-payee).

## Fehler und nächste Schritte

| Status / Code | Bedeutung |
|---|---|
| 400 `invalid_json` | Ungültiges JSON. |
| 400 `invalid_request` | Keine nicht leere IBAN/BIC-Zeichenkette oder beide Werte ausgefüllt. |
| 400 `invalid_bic_format` | BIC entspricht nicht dem erwarteten Format. |
| 402 | Unzureichender Zugang oder Einheiten; Antwortinhalt prüfen. |
| 429 | `Retry-After` abwarten; dies ist nicht das Monatskontingent. |

Ein HTTP-Fehler oder eine fehlende Quelle bedeutet nicht „kein Risiko“. Siehe [Fehlerreferenz](/de/docs/errors), [Rezepte](/de/docs/recipes), [Erste Schritte](/de/docs/onboarding) und [Datenquellen](/de/docs/data-sources).
